# Excel Final 规范生产流程

本文是 Excel Final 当前实现的唯一生产合同。不成熟 ground truth 只用于学习与差异审查；分类规则、物理关系、真实 MySQL 结果和可追溯性优先。

## 1. 输入与预处理

### 1.1 生产输入

- `.xlsx` / `.xlsm` 至少包含一张 worksheet；生产入口只处理第一张，并明确报告被忽略的其他 sheet。
- `.xlsm` 只作为输入容器；规范输出必须新建为 `.xlsx`，显式指定其他输出后缀直接拒绝，不承诺保留宏。
- Tekla 文本可使用 `.xls` 后缀；系统按文本适配，不把它误当作旧二进制 Excel。
- 唯一输入 Interface 自动选择标准工作簿、初始表工作簿、制表符 Tekla 文本或固定宽度 Tekla 文本 Adapter；CLI 和 backend 不重复猜格式。
- 标准工作簿若在同一物理行按换行叠放多条零件明细，以零件号条目数为锚逐项展开；单值字段明确共享、空字段保持空，非单值字段条目数不一致时返回带 sheet、原行和字段的输入错误，不猜配。
- 固定宽度文本按 Unicode 双宽显示列和数据 token 起点校准列跨度，保留中间空字段；不得用 `\s+` 压缩后按列号解释。
- 只有构件汇总、没有零件身份字段的输入明确拒绝，不伪造零件或 `part`。无法解码的私有二进制 `.xls` 按无法解码拒绝。
- 多表文件可直接进入生产流程，但仅第一张表作为输入；使用者应根据预检警告确认第一张确为 Tekla 原表。
- 输入路径和输出路径不得相同；写入使用同目录临时文件和原子替换，失败不覆盖已有结果。

### 1.2 题头检测

系统扫描候选行并按必需字段完整度评分。最高分必须唯一，且必须包含构件编号、零件号、规格、零件长度、材质和数量等生产字段；批次为可选上下文。集中别名覆盖构件号/构件编号、零件号/零件编号、规格/型材/截面型材/截面规格及重量面积常见名称。同一规范字段出现多个源列、完整度相同的多个候选行、缺失必需字段或重复长度列无法用语义分组消歧时，直接失败并给出候选诊断。

没有固定行号默认值。

### 1.3 原值与工作值

- `原表`保留原单元格值、样式和半角/全角空格。
- 工作值移除半角与全角空格，用于身份、规格和材质判断。
- 来源 sheet、来源行、来源序号、原数量、构件数、原规格和源重量全程保留。
- 拆板兄弟行共享父来源序号，不重新编号。

## 2. 统一领域记录

Tekla Adapter 根据已恢复字段判定构件起始行、零件行和小计行，不使用零件号命名正则猜行类型；随后合并为每构件一个 `summary`：身份字段优先取起始行，重量、面积和外形尺寸优先取小计行，双方重叠值不一致则记录严重冲突。构件数必须存在且大于零；已提供的构件长、宽、高必须大于零；构件重量和面积必须非负；所有数值必须有限。违反任一规则时记录来源行明确的严重问题并隔离整个构件。`构件表`同时记录起始来源行和小计来源行。初始表动态查找组件元数据与表头，不固定在第 1/2 行；它直接生成 summary，并把“单重/总重”映射为源单毛重/总毛重，源净重保持空白。

四类 Adapter 之后都进入 `canonical_pipeline.process_canonical_records`。分类、查询、计算、拆板、`part` 和写表不得在适配器中复制实现。

## 3. 规格分类

分类先于数据库查询，且一次完成。数据库不负责猜类别。

| 输入 | 规范类型/规格 | 查询策略 |
|---|---|---|
| 普通 `PLt*w` | 板材；规格=t，宽度=w | `plate_constant:7.85` |
| `PL6*30` | 扁钢；规格=`6*30`，宽度空 | `flat_steel` |
| `FB/FLAT/扁钢/扁铁` | 扁钢；规格=`t*w` | `flat_steel` |
| 裸 `t*w` | 先作为扁钢候选 | `flat_steel` 明确查无后才回退板材 |
| `BHh*b*tw*tf` | BH | 板材常数，允许拆板 |
| `BOXh*b*tw*tf` | BOX | 板材常数，允许拆板 |
| `BOXh*b*t` | BOX，`tw=tf=t` | 板材常数，允许拆板 |
| `BTh*b*tw*tf` | BT | 板材常数，允许拆板 |
| `PIP2000*60`、`PD114.3*6.3` | 圆管；规格=外径D，宽度=壁厚t | 圆管几何公式，不查库 |
| 普通工字钢 | 工字钢成品型材 | `i_beam`，不拆板 |
| D + HPB、Q235B 或 Q355B | 圆钢；Excel规格保留`D直径` | `round_bar`，查询键仅为直径数字 |
| D + HRB | 螺纹钢；Excel规格保留`D直径` | `rebar`，查询键仅为直径数字 |
| 螺栓、NUT/螺母、螺套、TT | 对应连接件类型 | 不查库；比重、理单重、理总重留空 |
| HA 或无法确定类别 | 未分类 | 标记查无，不跨类别猜测 |

对外持久化和 API 使用稳定英文类别代码，例如 `flat_steel`、`round_bar`、`rebar`；Excel 类型列使用中文业务标签。

明确 `PL` 保持书写顺序，不交换厚度和宽度。只有裸 `t*w` 在扁钢表零行命中时才按板材拆为厚度和宽度。

## 4. 五金手册 MySQL

### 4.1 查询边界

- 每个确认类别只能查询 allow-list 中对应的表和列。
- 不进行跨表顺序搜索。
- 不使用计算候选、跨类别扩散或静态杂项重量。
- `PIP/PD`在查询前已归为圆管公式类，不访问数据库。D系列查询去掉前缀，只把直径数字交给圆钢/螺纹钢表，但整理表规格仍保留`D`，例如`D8`显示为`D8`、查询键为`8`。只对其他手册类别做已由唯一源手册和真实数据库验证的键名适配：`HI→I`、`HN/HW/HM/HT→H`、`TN/TW/TM→T`、`C14A→[14A`、`IP/P/Φ/D→φ`、方管/矩形管→`□`、方钢→数值边长、`HFW→LH`。`LH` 查高频焊表，不查 H 型钢；整理表和 `part` 仍保留来源规格。
- W 型钢把源表分列的美标规格和中文规格分别保存为同源规范查询键；不拼接或补充任何源外重量。
- 板材常数为 `7.85`，不访问数据库。
- 连接件跳过查询，留空且不标查无。
- 其他确认类别若 `SELECT` 返回零行，`比重`写红色“查无”，`比重来源`写 `<table>:not_found`，并在最终提示和`处理报告`中出现。
- 唯一源手册同一查询键出现多个不同重量时，`比重`写红色“冲突”，报告列出对应源行；不得任取一条，也不得按查无规则回退为板材。
- H 型钢表按数据库的 `weight_2010`、`weight_2005`、`weight_98` 顺序取首个非空值。数据库没有现行 2024 版字段时不得宣称使用现行标准；源毛重若更接近其他版本，只报告“确认项目标准版本”，不反向挑选最接近源值的旧版。

### 4.2 故障语义

只有成功执行的 `SELECT` 零行是业务查无。连接失败、权限错误、schema 不符、SQL 错误、非数值/越界结果均为基础设施错误，整次处理失败。CLI 只输出安全摘要，不打印主机、DSN、密码或子进程 traceback。

运行库只能由唯一可信 `五金手册.xls` 生成：2025 条非空源行全部入库，1967 条物理语义记录逐行外键追溯；重复冲突键返回 `conflict`，不得任取一行。仓库在初始化时一次性验证所需表结构；同一类别、规格、材质组合使用进程内缓存。

## 5. 理论重量

所有内部计算使用 `Decimal` 和未舍入值；输出重量按三位小数展示，面积按两位小数展示。后端关系投影的物理数值使用 `DECIMAL(24,9)`，避免 MySQL 32 位 `FLOAT` 在项目累计时产生毫克到克级漂移；仅在 HTTP/Job JSON 边界转换为普通数字。

### 5.1 板材

```text
理单重 = 厚度(mm) × 宽度(mm) × 长度(mm) × 7.85 / 1,000,000
```

### 5.2 成品型材

```text
理单重 = 手册线重(kg/m) × 长度(mm) / 1,000
```

### 5.3 PIP/PD 圆管

```text
比重(kg/m) = (外径D - 壁厚t) × 壁厚t × 0.02466
理单重(kg) = 比重(kg/m) × 长度(mm) / 1,000
```

外径和壁厚单位均为 mm，且必须满足 `D>0`、`t>0`、`D>2t`。不合法时比重和理论重量留空，并报告“圆管规格无效”。

### 5.4 焊接组合截面

BBH、BH、BOX、BT 的父理论单重等于所有子板单块理论重乘每个父件所需块数后的合计，用于核验父源重量：

```text
BBH父理论单重 = BBH腹单块理重 × 1 + BBH翼单块理重 × 2（腹板按两端平均高度折算）
BH父理论单重  = BH腹单块理重 × 1 + BH翼单块理重 × 2
BOX父理论单重 = BOX腹单块理重 × 2 + BOX翼单块理重 × 2
BT父理论单重  = BT腹单块理重 × 1 + BT翼单块理重 × 1
```

拆板后每个子板行按自身厚度、宽度和长度计算单块理重，理总重乘该行拆后总数；所有子板行的理总重之和必须与父理论总重守恒。运行时若父理论单重与子板加权合计不相等，记录“拆板重量守恒异常”、停止生成该父件的子板和`part`。父源净重、毛重只在主子板行显示，不复制到其他子板；腹板和翼板行各自仍保留本子板的理论重。人工核对时不得把主行上的父毛重与该行单块腹板理重直接比较。

```text
理总重 = 父理论单重 × 原数量 × 构件数
```

## 6. 源重量物理核验

进入分类、手册查询、拆板和理论公式前先执行源行门禁：构件编号、零件号、规格、长度、材质、数量缺失，长度/数量/构件数非正，源重量/面积为负，或任一数值为 NaN/Infinity 等非有限数，均逐字段记录严重问题。原值仍保留在清洗表、整理表和报告并标红，但不进入 `part`；后端关系投影也拒绝缺构件身份或非有限数值。零重量允许继续按现有核验规则处理。

字段口径固定：

```text
单净重 × 原数量 ≈ 总净重
单毛重 × 原数量 ≈ 总毛重
总净重 × 构件数 = 表净重
总毛重 × 构件数 = 表毛重
```

`表净重`和`表毛重`是项目/批次汇总口径；不得直接把未乘构件数的总净重或总毛重作为批次总量。

### 6.1 基础物理冲突

- 源单/总重量链绝对误差超过 `0.1 kg`：严重。
- 单净重或总净重比对应毛重高出超过 `0.1 kg`：严重。
- 用户已确认 `0.1 kg` 用于吸收三位小数和累计舍入误差。

### 6.2 理论重与毛重

先看绝对误差，再看相对误差。单重绝对容差为 `0.01 kg`，总重绝对容差为 `0.01 kg × 原数量`，避免单重已通过后仅因累计舍入再次告警：

- 绝对误差在对应容差内：通过；
- 或相对误差 ≤ `0.5%`：通过；
- 相对误差 > `0.5%` 且 ≤ `2%`：警告；
- 手册标准型材相对误差 > `2%`：严重并隔离 `part`；
- 板材及 BBH/BH/BOX/BT 几何理论重超出通过范围：警告但不隔离 `part`。

表单重对应源单毛重；普通行的理单重对应按几何或五金手册得到的毛坯理论重。BBH/BH/BOX/BT 拆板行的可见理单重是单块子板理论重，而源单毛重是父构件重量并集中显示在主行，必须用5.4节的子板加权合计作为比较值。二者不是要求逐字相等，而是按上述物理容差核验。

分级差异来自物理口径：标准型材毛重原则上由型材目录截面积和长度决定，手册偏差可作为强核验；板材、轮廓板和参数化/焊接组合截面的源毛重可能按外包毛坯、切割前轮廓或模型体积计算，几何矩形理论重只能提示复核，不能单凭 >2% 判定源数据损坏。

### 6.3 净重与理论重

净重低于理论毛坯重符合材料利用率含义，不设低值截断。净重超过理论重时，绝对差 ≤`0.01 kg` 或相对差 ≤`0.5%` 通过，其他情况均为复核警告，不隔离 `part`。净重大于对应毛重仍按 6.1 的硬物理冲突判为严重。

源重量缺失时不以理论值回填，记录警告；明确跳过的连接件不因预期空值产生缺失警告。

## 7. 规范拆板

只拆分已分类为 BBH、BH、BOX、BT 且几何参数合法的父件。BBH/BH/BT 必须四参数；BBH 是变截面 BH，规格写成两端高度 `H1-H2`（也接受 `~`、`～`、`—` 分隔），腹板按两端平均高度折算；BOX 允许四参数或三参数等壁厚简写：

| 类型 | 腹板 | 翼板 |
|---|---|---|
| BBH | `tw × ((H1+H2)/2 - 2tf)`，数量=N | `tf × B`，数量=2N |
| BH | `tw × (H-2tf)`，数量=N | `tf × B`，数量=2N |
| BOX | `tw × (H-2tf)`，数量=2N | `tf × B`，数量=2N |
| BT | `tw × (H-tf)`，数量=N | `tf × B`，数量=N |

子板类型固定为 `BBH腹/BBH翼`、`BH腹/BH翼`、`BOX腹/BOX翼`、`BT腹/BT翼`。父原规格不可变；导入零件号为 `原零件号-类型`。

父单/总净重、单/总毛重、表净/毛重、利用率和面积只显示在腹板/主行；腹板和翼板各自显示7.85及本子板的理单重、理总重，其加权贡献共同组成父理论重。非法几何保留一条父整理行、记录严重问题，并从 `part` 排除，不能静默丢行。

## 8. part

`part`内部和最终 Excel 都是 12 列；最终表把“类型”移到 L 列：

```text
导入构件编号, 导入零件号, 规格, 宽度, 下料长度, 材质,
汇总, 班组, 图形, 备注, 文件, 类型
```

- 仅板材、扁钢和 BBH/BH/BOX/BT 子板进入。
- `备注`与`文件`是兼容预留列，所有数据行固定留空；`文件`固定在K列，不执行文件类型推断。
- L列“类型”只显示 `BBH腹/BBH翼/BH腹/BH翼/BOX腹/BOX翼/BT腹/BT翼`；板材、扁钢等其他行留空。内部合并和后端导入仍使用完整类别。
- 所有通过身份、几何和严重重量门禁的合法候选进入。
- `汇总 = 拆板后数量 × 构件数`，零值保持零。
- BBH/BH/BOX/BT 子板保留导入构件编号，并在构件范围内按完整属性汇总。
- 板材和扁钢清空导入构件编号，按导入零件号、规格、宽度、下料长度、材质、类型和班组跨构件汇总。
- 全局范围内同名不同规格、尺寸、材质或类型的零件分别输出，不能强制混合。
- 同一构件内同一 BBH/BH/BOX/BT 导入零件号若对应不同几何或材质，记录严重冲突并排除。
- 输出先列按构件排序的 BBH腹、BBH翼、BH腹、BH翼、BOX腹、BOX翼、BT腹、BT翼，再列全局汇总的扁钢和板材。
- 原始输入没有班组或图形来源时保持空白，不从样本 GT 反向注入。
- 当前 `part`是未分班组的汇总；`整理表`继续保留构件级来源，供后续分班组操作建立数量基准。

## 9. 固定六表与样式

输出 sheet 顺序固定：

1. `原表`
2. `清洗表`
3. `构件表`
4. `整理表`
5. `part`
6. `处理报告`

整理表内部计算记录为35个字段；最终Excel输出32列，包含来源序号、构件/导入身份、原数量/拆后数量/总数、三组重量链、面积和保留下来的算术公式。最终只删除“比重来源”“净材利用率”“重量核验”3个审计列；“类型”保留，但只有八种 BBH/BH/BOX/BT 子板类型显示，其他行留空。内部导入副本和数据库仍保留完整类别及审计字段。

构件表内部仍保留来源 sheet、行类型和小计来源行，用于合并来源与质量定位；最终 Excel 删除这 3 列，输出其余 15 列。

后端生产执行会在Job临时目录请求一份完整内部工作簿，并以该文件导入数据库中的类型、比重来源、利用率、重量核验和构件来源；随后仅将完成最终删列但保留可见算术公式的工作簿写入对象存储。内部工作簿不进入下载结果，任务临时目录结束后清除。独立CLI默认不生成内部副本。

`清洗表`、`构件表`、`整理表`、`part`和`处理报告`按最终表头与实际内容计算列宽。中文及全角字符按双宽计，普通列限制为 8–32；处理报告的“说明”和“建议操作”限制为 16–48，并对内容启用自动换行和顶部对齐。`原表`不参与调整，输入文件已有列宽保持不变。

整理表中的程序算术结果均保留公式：`下料长度=长度-左进-右进`、`总数=构件数×数量`、`总长=长度×总数`；板材和 BBH/BH/BOX/BT 子板理论重按厚×宽×长×7.85计算，PIP/PD 的比重按圆管公式计算，手册型材按手册米重×长度计算；`理总重=未舍入理单重×总数`，`表净/表毛=源总净/毛重×构件数`。净材利用率只作为内部审计字段，普通行按单净重÷理论单重，拆板主行仍按父净重÷父理论重，最终工作簿删除该列。没有完整计算依据的单元格保持空白，不伪造为零。`part.汇总`使用明确的整理表贡献行求和公式，完整属性不同的行不会混入。

保存后分别修补整理表和part目标 worksheet 的 OOXML `<f>` 与 `<v>`，并用公式模式和`data_only`模式双重回读；任一公式文本或缓存值不一致则整次写入失败。回读使用内存索引，避免只读随机访问对数千个公式形成平方级扫描。

查无单元格使用红色字体。严重物理问题对应的可见重量单元格使用红色字体和浅红填充，问题详情进入处理报告。

`处理报告`固定为“级别、类别、来源位置、构件编号、零件号、涉及字段、说明、建议操作”8列，只收录警告、严重和致命问题。同一来源行存在严重/致命问题时，不再重复上报该行的几何/手册理论重或净重口径次级警告；查无、字段缺失等独立问题仍保留。普通几何理论偏差按“高于/低于几何理论重”聚合；BBH/BH/BOX/BT 单独按拆板类型和数量倍率说明“拆板合计父理论重”，两者不得混组。报告给出最大相对偏差；手册偏差仍按规格保留，便于确认标准版本；其他问题按级别、类别、来源 sheet、规格/查找对象和建议操作跨行聚合。每条说明影响行数并最多列三个代表来源。警告、严重和类别计数以最终报告合并行数为准，与 backend 回读口径一致；信息级记录不进入报告和对外摘要。没有人工处置项时保留表头并在`A2`写“无”。

## 10. 质量状态与返回值

- `ok`：没有警告或严重问题；信息级记录不进入最终报告。
- `warning`：至少一个警告，没有严重问题。
- `severe_warning`：至少一个严重问题。

生产入口返回 `PipelineOutcome`：输出路径、质量状态、警告计数、严重计数和按类别汇总的报告摘要。它实现 `__fspath__`，旧后台可暂时使用 `Path(result)`；版本化 JSON 协议由 backend 负责。
