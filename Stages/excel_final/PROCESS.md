# Excel Final 规范生产流程

本文是 Excel Final 当前实现的唯一生产合同。不成熟 ground truth 只用于学习与差异审查；分类规则、物理关系、真实 MySQL 结果和可追溯性优先。

## 1. 输入与预处理

### 1.1 生产输入

- `.xlsx` / `.xlsm` 必须恰好包含一张 worksheet。
- `.xlsm` 只作为输入容器；规范输出必须新建为 `.xlsx`，显式指定其他输出后缀直接拒绝，不承诺保留宏。
- Tekla 文本可使用 `.xls` 后缀；系统按文本适配，不把它误当作旧二进制 Excel。
- 多表复核文件不得直接进入生产流程。先运行预处理工具，只复制指定原表到新工作簿。
- 输入路径和输出路径不得相同；写入使用同目录临时文件和原子替换，失败不覆盖已有结果。

### 1.2 题头检测

系统扫描候选行并按必需字段完整度评分。最高分必须唯一，且必须包含构件编号、零件号、规格、零件长度、材质和数量等生产字段。完整度相同的多个候选行、缺失必需字段或重复长度列无法用语义分组消歧时，直接失败并给出候选诊断。

没有固定行号默认值。

### 1.3 原值与工作值

- `原表`保留原单元格值、样式和半角/全角空格。
- 工作值移除半角与全角空格，用于身份、规格和材质判断。
- 来源 sheet、来源行、来源序号、原数量、构件数、原规格和源重量全程保留。
- 拆板兄弟行共享父来源序号，不重新编号。

## 2. 统一领域记录

Tekla 适配器先识别构件起始行和小计行，再合并为每构件一个 `summary`：身份字段优先取起始行，重量、面积和外形尺寸优先取小计行，双方重叠值不一致则记录严重冲突。构件数必须存在且大于零；已提供的构件长、宽、高必须大于零；构件重量和面积必须非负；所有数值必须有限。违反任一规则时记录来源行明确的严重问题并隔离整个构件。`构件表`同时记录起始来源行和小计来源行。初始表直接生成 summary，并把“单重/总重”映射为源单毛重/总毛重，源净重保持空白。

两个适配器之后都进入 `canonical_pipeline.process_canonical_records`。分类、查询、计算、拆板、`part` 和写表不得在适配器中复制实现。

## 3. 规格分类

分类先于数据库查询，且一次完成。数据库不负责猜类别。

| 输入 | 规范类型/规格 | 查询策略 |
|---|---|---|
| 普通 `PLt*w` | 板材；规格=t，宽度=w | `plate_constant:7.85` |
| `PL6*30` | 扁钢；规格=`6*30`，宽度空 | `flat_steel` |
| `FB/FLAT/扁钢/扁铁` | 扁钢；规格=`t*w` | `flat_steel` |
| 裸 `t*w` | 先作为扁钢候选 | `flat_steel` 明确查无后才回退板材 |
| `BHh*b*tw*tf` | BH | 板材常数，允许拆板 |
| `BOXh*b*tw*tf` | BOX | 板材常数，允许拆板 |
| `BTh*b*tw*tf` | BT | 板材常数，允许拆板 |
| 普通工字钢 | 工字钢成品型材 | `i_beam`，不拆板 |
| D + HPB 或 Q355B | 圆钢 | `round_bar` |
| D + HRB | 螺纹钢 | `rebar` |
| 螺栓、NUT/螺母、螺套、TT | 对应连接件类型 | 不查库；比重、理单重、理总重留空 |
| HA 或无法确定类别 | 未分类 | 标记查无，不跨类别猜测 |

对外持久化和 API 使用稳定英文类别代码，例如 `flat_steel`、`round_bar`、`rebar`；Excel 类型列使用中文业务标签。

明确 `PL` 保持书写顺序，不交换厚度和宽度。只有裸 `t*w` 在扁钢表零行命中时才按板材拆为厚度和宽度。

## 4. 五金手册 MySQL

### 4.1 查询边界

- 每个确认类别只能查询 allow-list 中对应的表和列。
- 不进行跨表顺序搜索。
- 不使用计算候选、别名扩散或静态杂项重量。
- 板材常数为 `7.85`，不访问数据库。
- 连接件跳过查询，留空且不标查无。
- 其他确认类别若 `SELECT` 返回零行，`比重`写红色“查无”，`比重来源`写 `<table>:not_found`，并在最终提示和`处理报告`中出现。

### 4.2 故障语义

只有成功执行的 `SELECT` 零行是业务查无。连接失败、权限错误、schema 不符、SQL 错误、非数值/越界结果均为基础设施错误，整次处理失败。CLI 只输出安全摘要，不打印主机、DSN、密码或子进程 traceback。

仓库在初始化时一次性验证所需表结构；同一类别、规格、材质组合使用进程内缓存。

## 5. 理论重量

所有内部计算使用 `Decimal` 和未舍入值；输出重量按三位小数展示，面积按两位小数展示。后端关系投影的物理数值使用 `DECIMAL(24,9)`，避免 MySQL 32 位 `FLOAT` 在项目累计时产生毫克到克级漂移；仅在 HTTP/Job JSON 边界转换为普通数字。

### 5.1 板材

```text
理单重 = 厚度(mm) × 宽度(mm) × 长度(mm) × 7.85 / 1,000,000
```

### 5.2 成品型材

```text
理单重 = 手册线重(kg/m) × 长度(mm) / 1,000
```

### 5.3 焊接组合截面

BH、BOX、BT 的父理论单重等于所有子板截面积贡献之和乘长度和 7.85。拆板只改变几何投影，不分摊或复制父源重量。

```text
理总重 = 父理论单重 × 原数量 × 构件数
```

## 6. 源重量物理核验

进入分类、手册查询、拆板和理论公式前先执行源行门禁：构件编号、零件号、规格、长度、材质、数量缺失，长度/数量/构件数非正，源重量/面积为负，或任一数值为 NaN/Infinity 等非有限数，均逐字段记录严重问题。原值仍保留在清洗表、整理表和报告并标红，但不进入 `part`；后端关系投影也拒绝缺构件身份或非有限数值。零重量允许继续按现有核验规则处理。

字段口径固定：

```text
单净重 × 原数量 ≈ 总净重
单毛重 × 原数量 ≈ 总毛重
总净重 × 构件数 = 表净重
总毛重 × 构件数 = 表毛重
```

`表净重`和`表毛重`是项目/批次汇总口径；不得直接把未乘构件数的总净重或总毛重作为批次总量。

### 6.1 基础物理冲突

- 源单/总重量链绝对误差超过 `0.1 kg`：严重。
- 单净重或总净重比对应毛重高出超过 `0.1 kg`：严重。
- 用户已确认 `0.1 kg` 用于吸收三位小数和累计舍入误差。

### 6.2 理论重与毛重

先看绝对误差，再看相对误差：

- 绝对误差 ≤ `0.01 kg`：通过；
- 或相对误差 ≤ `0.5%`：通过；
- 相对误差 > `0.5%` 且 ≤ `2%`：警告；
- 相对误差 > `2%`：严重。

表单重对应源单毛重；理单重对应按几何或五金手册得到的毛坯理论重。二者不是要求逐字相等，而是按上述物理容差核验。

### 6.3 净重与理论重

净重低于理论毛坯重符合材料利用率含义，不设低值截断。净重超过理论重时，≤0.5% 通过，0.5%–2% 警告，>2% 严重。

源重量缺失时不以理论值回填，记录警告；明确跳过的连接件不因预期空值产生缺失警告。

## 7. 规范拆板

只拆分已分类为 BH、BOX、BT 且四个几何参数合法的父件：

| 类型 | 腹板 | 翼板 |
|---|---|---|
| BH | `tw × (H-2tf)`，数量=N | `tf × B`，数量=2N |
| BOX | `tw × (H-2tf)`，数量=2N | `tf × B`，数量=2N |
| BT | `tw × (H-tf)`，数量=N | `tf × B`，数量=N |

子板类型固定为 `BH腹/BH翼`、`BOX腹/BOX翼`、`BT腹/BT翼`。父原规格不可变；导入零件号为 `原零件号-类型`。

父单/总净重、单/总毛重、表净/毛重、比重、理论重、利用率和面积只显示在腹板/主行；翼板保持空白，但其理论截面贡献仍参与父理论重。非法几何保留一条父整理行、记录严重问题，并从 `part` 排除，不能静默丢行。

## 8. part

`part`固定 11 列：

```text
导入构件编号, 导入零件号, 规格, 宽度, 下料长度, 材质,
汇总, 班组, 图形, 类型, 文件
```

- 仅板材、扁钢和 BH/BOX/BT 子板进入。
- `文件`是兼容保留列，所有数据行固定留空，不执行文件类型推断。
- 所有通过身份、几何和严重重量门禁的合法候选进入。
- `汇总 = 拆板后数量 × 构件数`，零值保持零。
- 不跨构件汇总。
- 同一构件内同一导入零件号若对应不同几何或材质，记录严重冲突并排除。
- 类型顺序为 BH腹、BH翼、BOX腹、BOX翼、BT腹、BT翼、扁钢、板材。
- 原始输入没有班组或图形来源时保持空白，不从样本 GT 反向注入。

## 9. 固定六表与样式

输出 sheet 顺序固定：

1. `原表`
2. `清洗表`
3. `构件表`
4. `整理表`
5. `part`
6. `处理报告`

整理表固定 35 列，包含来源序号、构件/导入身份、原数量/拆后数量/总数、手册来源、三组重量链、利用率和核验状态。

长度存在时，`下料长度(mm)`写公式 `=长度-左进-右进`；长度缺失时公式与缓存均保持空白，不伪造为零。保存后只修补目标 worksheet 的 OOXML `<f>` 和 `<v>`，并用公式模式与 `data_only` 模式双重回读；任一不一致则整次写入失败。

查无单元格使用红色字体。严重物理单元格及`重量核验`使用红色字体和浅红填充。`处理报告`一条来源问题一行，不用单元格颜色数量代替报告计数。

## 10. 质量状态与返回值

- `ok`：没有警告或严重问题；信息级记录允许存在。
- `warning`：至少一个警告，没有严重问题。
- `severe_warning`：至少一个严重问题。

生产入口返回 `PipelineOutcome`：输出路径、质量状态、警告计数、严重计数和按类别汇总的报告摘要。它实现 `__fspath__`，旧后台可暂时使用 `Path(result)`；版本化 JSON 协议由 backend 负责。
