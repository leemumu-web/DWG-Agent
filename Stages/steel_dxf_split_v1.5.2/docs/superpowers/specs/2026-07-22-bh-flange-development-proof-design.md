# BH 翼缘展开生产证明设计

## 目标

在保持 BH v1.5.2 单内核、来源可追溯和失败关闭原则不变的前提下，解决
`2b1-cb-40` 与 `2b2-cb-10` 因 `BH.PROOF.FLANGE.DEVELOPMENT` 缺少生产授权而进入
`review_required` 的问题，使已批准的 `project_tekla_bh_dxf_v1` 来源域达到
`20 auto_accept / 0 review_required / 0 rejected`。

本改动属于 BH v1.5.2 基线上的一个有声明、可验证的制造语义补丁。它不改变 BOX
内核，不新增双跑、投票、结果融合、回退路由或人工结果运行时依赖。

## 已确认事实

当前算法已经从源图恢复正确的腹板、孔、翼缘角色和原始展开候选，但没有授权将
推导长度变成生产长度：

- `2b1-cb-40` 的原始两条翼缘路径为 `2538.2049559516026 mm` 与
  `2383.037 mm`；人工制造结果为 `2538 mm` 与 `2383.037 mm`。
- `2b2-cb-10` 的唯一材料表一致路径为 `11294.91280748483 mm`；人工制造结果为
  `11294 mm`，数量为 2。
- 历史 BH 实现曾对推导路径执行向下整毫米量化，但该规则仅以监督图为理由，因而在
  v1.5.2 中被移除并改为复核。
- 生产编译必须在读取人工参考之前冻结结果；人工参考只能进行离线验收。

## 采用方案

采用“来源拓扑证明 + 已批准 profile 制造策略”。不直接恢复历史 `floor()`，而是把
量化方式纳入现有 `BHKnowledgeBase`，由来源合同、方言 profile、几何证书和发布证据
共同约束。

### 制造策略

在 `BHKnowledgeBase` 中增加冻结的翼缘展开策略，至少包含：

- `derived_length_quantum_mm = 1.0`
- `derived_length_rounding = "floor"`
- `preserve_direct_projection = true`
- `require_unique_cranked_candidate = true`

该策略只对 `project_tekla_bh_dxf_v1` 的已验证 Tekla 单构件 BH 图生效，并自动进入
知识指纹与发布证据。它不是 CLI 开关，也不能由单张图或文件名覆盖。

### 直条变高翼缘

`variable_height_two_paths` 的每条路径分别分类：

1. 若路径与已绑定的 1:1 直接投影长度在制造容差内一致，则保留源坐标精度；
2. 否则只有在下列证书全部通过时才允许作为推导长度：
   - 闭合源轮廓完整且来源实体可追溯；
   - 两条主边平行，投影厚度与 `tf` 一致；
   - 主方向投影唯一，矩形填充率满足既有严格阈值；
   - 所属视图、单位、比例和来源合同有效；
   - 候选搜索完整且没有同等合法的竞争路径。
3. 通过证书的推导长度按策略向下量化到 1 mm；否则保持复核。

这会得到 `2538 mm` 与直接投影的 `2383.037 mm`，而不是统一舍入所有翼缘。

### 折线翼缘

`constant_height_cranked_path` 不再无条件选择最接近材料表 `LENGTH` 的边界路径：

1. 从闭合源面中区分纵向路径链和端部封口链；
2. 保留每个候选链的源实体、端点、段序列和原始长度；
3. 使用材料表显示精度或真正绑定的总尺寸筛选候选；
4. 必须恰好有一个候选落在显示精度容差内；零个或多个均为证据不足；
5. 两块物理翼缘在量化后的外形、属性、孔和开口必须满足既有数量合并证明；
6. 唯一候选通过后按策略向下量化到 1 mm。

这会得到 `11294 mm`。材料表只参与唯一候选绑定，不能单独创造几何，也不能用
“最近值”掩盖冲突。

## 证明与路由

`BH.PROOF.FLANGE.DEVELOPMENT` 增加两种可通过的来源证书：

- `profile_authorized_rigid_development`
- `profile_authorized_cranked_development`

证明报告必须同时记录原始长度、量化后长度、量化策略、来源 ID、候选总数、匹配
候选数和绑定证据。只有关键证书完整时才为 `PASS`；任何来源缺失、候选不唯一、
profile 不匹配或搜索不完整仍进入 `review_required` 或既有拒绝路由。

不得出现构件号、文件哈希、固定页面坐标、人工结果路径或特定长度分支。

## 代码边界

保持现有架构，仅局部修改：

- `bh_knowledge.py`：声明 profile 级制造策略；
- `bh_geometry.py`：保留原始观察、形成严格候选证书并在授权后量化；
- `bh_development.py`：评估证书与制造权限；
- `bh_constraints.py`：让关键证明消费证书，不再只接受显式总尺寸；
- 相关报告、语料 manifest、发布证据和测试：反映新能力边界。

不增加新的 worker 路由器、适配器或第二套 BH 算法。

## 失败处理

- 未配置或不匹配的展开策略：`review_required`；
- 直条厚度、平行性、闭包或来源守恒不满足：`review_required`；
- 折线路径没有唯一绑定候选：`review_required`；
- 搜索不完整、来源冲突或制造几何非法：沿用既有拒绝/无法处理语义；
- 编程异常：继续作为 worker 失败暴露，不得包装成工程复核。

## 测试与验收

### 测试先行

先增加失败测试，固定：

- `2b1-cb-40` 为生产路由，翼缘长度为 `2538`、`2383.037`；
- `2b2-cb-10` 为生产路由，翼缘长度为 `11294`、数量 2；
- 20 张人工离线几何对比全部通过；
- 缺少 profile 策略、直条证书破坏、折线零匹配或多匹配时不得自动通过；
- 生产模块不读取人工参考或样本标识。

### 回归门禁

1. BH 20 张：`20/20 auto_accept`，保存后 DXF 验证和人工离线比较通过；
2. BH 160 次表示变换：制造 payload 和处置不变；
3. BOX 权威 20 张和项目 2 的 30 张：结果不变；
4. Windows 公共 `split_dxf`：BH/BOX 自动识别、完整输出、报告和确定性通过；
5. Ruff、格式、编译、当前测试清单和源码来源审计通过；
6. Linux 原生环境完成依赖、POSIX 进程监督、完整测试、语料批处理和发布证据门禁。

## 发布影响

制造权限边界改变后，旧 BH release evidence 必须失效。完成候选验证后重新生成并固定
知识指纹、能力摘要和 `20/0/0` 路由证据，再以正常发布路径复验。BOX 的 release
attestation 独立处理，不因本补丁改变。
