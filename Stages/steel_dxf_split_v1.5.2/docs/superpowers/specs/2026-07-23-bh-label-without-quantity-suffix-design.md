# BH 与 BOX 标签精简设计

## 目标

BH 与 BOX 输出 DXF 的零件标签统一不显示 `×2`，并将角色文字缩短为 `翼` 和 `腹`。例如：

```text
p=6b5-cb-1翼缘板×2
p=6b5-cb-1腹板
```

改为：

```text
p=6b5-cb-1翼
p=6b5-cb-1腹
```

## 范围

- 修改 BH 输出标签的自然语言文本。
- 保留内部 `quantity=2` 数量语义。
- 保留相同上下翼缘板合并为一个制造轮廓的现有行为。
- 不修改板件几何、孔洞、焊接余量、排版或报告数量字段。
- 两块不同翼缘板不再使用 `-1`、`-2`，分别标为 `p=<编号>上翼`、`p=<编号>下翼`。
- BOX 同样使用全局简写：等价板合并时为 `p=<编号>腹`、`p=<编号>翼`；不等价板分开时为 `p=<编号>上腹`、`p=<编号>下腹`、`p=<编号>上翼`、`p=<编号>下翼`。

## 实现

保留 `canonical_bh_label()` 的现有调用接口，包括 `quantity` 和 `index` 参数，以免扩大调用方改动；函数不再把数量追加到可见标签，并把 `web` 映射为 `腹`、合并翼缘映射为 `翼`、两个不同翼缘按既有顺序映射为 `上翼` 和 `下翼`。装配体验证器同步精确验证这些短标签，避免继续要求旧的 `腹板`、`翼缘板` 文本。

BOX 的 `canonical_box_label()` 已符合相同的全局短标签契约，因此不修改 BOX 几何或生成算法，只补齐合并与分开板件的全角色回归测试，防止以后重新出现长角色名或数量后缀。

## 验证

1. 先修改现有命名测试，确认它因当前仍输出 `腹板`、`翼缘板` 而失败。
2. 最小修改标签生成逻辑并确认命名测试通过。
3. 运行 BH、BOX 标签测试和完整测试集。
4. 重新处理 11 张 BH 输入，确认所有正常版和余量版标签均为 `p=<编号>翼` 或 `p=<编号>腹`，且几何与成对验证仍通过。
5. 检查现有 BOX 产物的标签均符合短标签契约。
6. 用新产物替换桌面交付目录中 11 组 BH 的正常产出和余量产出；源文件与 BOX 目录保持不变。

## 成功标准

- 22 个新 BH DXF 均使用 `翼`、`腹` 短标签，且无 `×2`。
- 11 组 BH 仍全部自动验收通过。
- BOX 合并及分开板件均由测试证明使用 `腹`、`翼`、`上腹`、`下腹`、`上翼`、`下翼`，且无旧长角色名或 `×2`。
- 本次小批次不重新生成或覆盖 BOX 产物。
- 桌面交付目录仍为 18 个编号目录、每个目录 3 个 DXF。
