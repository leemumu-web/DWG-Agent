# BH 制造语义编译器 v1.1：总体设计、语义边界与验证

## 1. 设计目标

真实深化图不是几何数据库，而是一种面向工程师的二维表达语言。同一个物理构件可能由多个投影、隐藏边、尺寸、孔符号、材料表和剖面共同描述。制造拆板需要恢复的是物理板件，而不是复制某一组图元。

因此系统的目标是：

```text
保留观察事实
→ 建立多个工程解释
→ 对完整解释执行物理与制造约束
→ 冻结可审计制造合同
→ 生成确定性生产结果
```

## 2. 领域编译器映射

| 编译器概念 | BH 拆板系统 |
|---|---|
| 源语言 | DXF 块、图层、实体、文字和投影约定 |
| 词法单元 | LINE、ARC、CIRCLE、TEXT、INSERT、线型和图层 |
| Source IR | 带来源和变换的事实对象 |
| 类型系统 | BH Profile、WebPlate、FlangePlate、CircularCut、Opening |
| 名称解析 | 材料表、PartMark、截面和构件编号的空间关联 |
| 控制流/候选 | 多个视图角色和完整装配假设 |
| 静态语义分析 | 物理组成、截面一致性、特征归属、来源完整性 |
| 优化 | 最小修复、证据覆盖、投影拟合和候选分离度 |
| IR Lowering | 投影视图到 Manufacturing IR |
| 代码生成 | 清洁 DXF R2007 |
| ABI/合同 | 稳定制造合同与语义指纹 |
| 回归测试 | 人工拆板监督、合同测试、确定性测试和输出审计 |

## 3. 为什么必须保留多个完整假设

局部视图分类具有不确定性。一个块可能在尺寸上像主视图，但孔分布、板高、翼缘宽度或来源关系与完整 BH 装配矛盾。若局部选择立即提交，后续只能在错误前提上修补。

v1.1 的求解单位是完整构件假设：

```text
Hypothesis
├── metadata interpretation
├── web projection
├── flange projection
├── web plate geometry
├── physical flange plates
├── owned cuts and openings
├── repair ledger
├── provenance
├── hard-rule results
├── soft evidence
└── semantic cost
```

只有完整降级后，候选才可比较。

## 4. 语义不等于机器学习潜向量

本系统的“语义理解”是显式、可验证的领域语义：

- 知道投影不是物理对象；
- 知道 BH 必须由一块腹板和两块物理翼缘板组成；
- 知道同一翼缘几何可表示数量 2，但切割特征不同则必须拆开；
- 知道孔必须归属于具体板件；
- 知道中心十字线是证据，不是切割对象；
- 知道隐藏 ARC 只有在完整几何证据成立时才能恢复为制造圆弧；
- 知道证据冲突时应复核或拒绝，而不是强行输出。

这些语义被编码为类型、规则、合同和图关系，而不是不可解释的文件名条件。

## 5. 信息层级

### 5.1 事实层

事实层不做业务判断：

- 源文件和单位；
- INSERT 变换；
- 实体类型、图层、线型和坐标；
- 文字内容和空间位置；
- 块与实体来源链。

### 5.2 几何层

- 节点、边、环、面和邻接；
- 平行、共线、相交和包含；
- 可见边、隐藏边和圆弧证据；
- 几何修复及其代价。

### 5.3 工程语义层

- BH 截面；
- 投影视图角色；
- 腹板与翼缘身份；
- 物理板数量；
- 特征归属；
- 标注一致性。

### 5.4 制造层

- 闭合外轮廓；
- 圆孔和异形开口；
- 厚度、数量、标签；
- 来源和制造合同。

后端只能读取制造层，不能重新解释源图。

## 6. 硬约束、软证据与合同

硬约束回答“能否制造”；软证据回答“多个合法解释中哪个更可信”。

制造合同将内部规则映射为稳定领域接口：

1. `source_integrity`：来源和最小干预；
2. `physical_model`：一腹板两翼缘、纵向合理性；
3. `manufacturing_safety`：轮廓、孔、开口和输出安全；
4. `projection_correspondence`：不同投影角色和尺寸拟合；
5. `supporting_evidence`：尺寸、孔标、零件标和剖面。

下游可以依赖合同，而不必理解求解器内部评分公式。

## 7. 候选恢复与最小修复

候选前沿通过多样化选择防止单一先验垄断：

- 最低全局代价；
- 每个角色的最佳候选；
- 代价窗口内候选；
- 覆盖不同块和证据通道的候选。

几何修复不是默认行为。允许的修复包括端部面补全、微小毛刺正则化和精确圆弧恢复。每项修复必须：

- 有明确证据；
- 受截面和名义长度约束；
- 保持拓扑合法；
- 记录在 repair ledger；
- 进入软代价。

## 8. 特征归属

每块板独立拥有切割特征：

```text
Plate
├── circular_cuts[]
└── inner_contours[]
```

归属过程先依据投影包含关系生成候选，再用板长、边视孔、侧向关系和冲突约束消歧。无法唯一归属时不得复制到多块板，应进入复核或拒绝。

## 9. 确定性与可追踪性

编译器输出：

- Source Fact IR 指纹；
- Selected Hypothesis 指纹；
- Manufacturing IR 指纹；
- 语义图；
- 编译阶段记录；
- 候选及拒绝原因；
- 制造合同；
- 自动化处置和置信度分解。

这使工程问题可定位到具体阶段，而不只是“输出轮廓不一致”。

## 10. 显式风险分析

规则说明“候选满足什么条件”，风险登记表说明“真实工程中可能怎样失败以及由什么机制阻止”。两者是互补关系。

每个风险对象包含：

```text
risk_id
severity
failure_mode
detection_stage
required_evidence
guard_mechanisms
applicable
status
active_guards
evidence
```

关键风险或高风险只有 `guarded` 或 `not_applicable` 时，编译结果才允许进入生产质量门。风险适用但证据不足时进入复核；防护失败时直接拒绝。

## 11. 失败分析模式

新样本失败时按以下顺序分析，而不是添加文件名分支：

1. 是否遗漏一种源事实？
2. 是否遗漏一种几何关系？
3. 是否过早丢弃候选？
4. 是否缺少物理不变量？
5. 是否缺少特征归属证据？
6. 是否需要一种受控修复？
7. 质量门是否应进入复核而非自动接受？

## 12. 验证金字塔

### 11.1 单元与契约验证

- 规则映射；
- 合同分层；
- 指纹规范化；
- 候选前沿；
- 置信度和处置。

### 11.2 20 组监督回归

每组重新从拆板前 DXF 编译，并与人工拆板后文件比较：

- 板件数量；
- 外轮廓 Hausdorff 距离；
- 面积和包围盒；
- 圆孔数量、孔径和孔心；
- 异形开口；
- 名称和数量。

### 11.3 输出安全验证

- DXF 审计错误为 0；
- 所有板轮廓闭合；
- `LINE/XLINE/RAY=0`；
- 十字线、尺寸和隐藏线未进入生产图。

### 11.4 确定性验证

- 重复编译指纹一致；
- 轮廓起点和方向不影响制造指纹；
- 重复编译清洁 DXF 字节一致。

### 11.5 进程隔离验证

每个大型测试节点和每张批处理图纸使用独立进程，避免原生资源生命周期影响测试或生产批次。

## 13. 验证结论

v1.1.0 的 20 组 BH 语料全部达到：

- 人工监督通过；
- 制造合同 `production_ready`；
- 关键和高风险均受控，无 `failed` 风险；
- 自动化处置 `auto_accept`；
- DXF 审计清洁；
- 无辅助线；
- 唯一且稳定的制造语义指纹。

115 个原子测试节点全部通过。BOX 兼容入口也通过原有 6 项测试，但不属于本轮语义重构范围。

## 14. 后续扩展

下一阶段应优先增加真正的新语义维度，而不是更多几何例外：

- 关联尺寸约束图；
- 焊缝、坡口和装配基准；
- 材料质量守恒；
- 多构件图纸分区；
- BH 之外的截面家族知识库；
- 人工复核界面与证据可视化。
