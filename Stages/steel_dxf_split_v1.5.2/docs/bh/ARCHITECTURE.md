# BH/BOX 统一双产物架构

## 总体边界

融合后的主程序由一个编排层、两个领域处理器和一个成对发布器组成：

```text
cli.py
→ pipeline.py
   ├─ profile_detection.py：只判型一次
   ├─ bh_pipeline.py：BH 原生拆板核心
   └─ box/compiler.py：BOX 原生拆板核心
→ hole_color_policy.py：左红右白的共享确定性策略
→ BH 或 BOX weld_allowance.py：从普通版复制派生余量版
→ paired_output.py：双文件一致性与余量闭合验收
→ 整个任务目录原子发布
```

统一层不解释、合并或投票决定 BH/BOX 制造几何。判型后只调用一个核心；核心完成拆板、制造证明和保存后验证，统一层只编排同源双产物及最终路由。

## 单次处理状态

每个输入任务经历以下不可重复阶段：

1. 从启动时冻结的输入目录快照取出源文件。
2. 打开源 DXF 并自动识别 `BH` 或 `BOX`。
3. 只调用匹配领域核心一次，在任务临时目录生成完整普通拆板结果。
4. 对普通结果执行一次余量变换，生成余量伸长结果。
5. 重开两份 DXF，验证单位、实体集合、孔洞几何、孔洞颜色和逐板余量闭合。
6. 在临时目录写齐报告与预览。
7. 将完整任务目录一次性提升到最终路由，并删除同名任务的旧相反路由。

运行时不会读取拆板后参考图，不会扫描普通版输出，不会把 `output` 再作为输入，也没有旧入口 fallback。

## 成对事务

`auto_accepted` 是任务级状态，不是单文件状态。普通版和余量版必须同时存在、同时通过，才允许发布。目录提升前若任一检查失败，普通候选与失败信息整体进入 `manual_review`；自动验收目录不会保留孤立文件。

同名任务重跑时，发布器同时处理目标路由和相反路由：

- 新结果自动通过：替换 `auto_accepted`，移除旧 `manual_review`；
- 新结果需要复核：替换 `manual_review`，移除旧 `auto_accepted`；
- 目录提升失败：恢复提升前的两个路由状态。

## 孔洞颜色

共享策略只接受唯一、无歧义的圆孔镜像对。板件局部 X 中线左侧为 ACI 1，右侧为 ACI 7；无法证明对称关系时全部保持 ACI 7。BH/BOX 写入器和保存后验证器调用同一策略，余量处理把颜色纳入不可变几何指纹，成对验收器再次比较两份文件的显式颜色。

## 领域核心稳定性

BH 与 BOX 的拆板、孔洞识别和余量几何算法仍位于各自领域模块。此次统一改造没有把两套制造 IR 合并，也没有用共享启发式替代核心几何求解。核心层的直接变化仅包括：

- 写入和验证孔洞颜色；
- 将孔洞显式颜色纳入余量不变性证明；
- BOX 余量读取器使用当前编译报告 schema 与路由常量；
- Windows 不支持 `O_DIRECTORY` 时跳过目录 fsync，文件原子写入保持不变。

因此影响面集中在输出语义、同源派生和发布事务；拆板轮廓算法本身保持领域隔离。
