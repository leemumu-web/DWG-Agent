# DXF 零件类型分类器设计

## 1. 目标与边界

项目提供一个独立 Linux 命令行程序，接收名称严格为 `<项目名称>_dxf` 的目录，只读取该目录第一层的 `.dxf` 文件，并把原文件复制到同级的 `<项目名称>_<零件类型>_dxf` 目录。程序不修改 DXF，不递归扫描，不从文件名推断零件类型，也不调用 BH 拆板编译器。

分类事实来自零件图右上信息表中与“截面”字段明确配对的值。材料表、尺寸标注、说明文字和零件几何只作为排歧上下文，不能越权成为类型结论。证据不足时必须停止自动分类。

## 2. 输出契约

输入示例：

```text
/data/项目2_dxf/
  A001.dxf
  A002.dxf
```

输出位于输入目录的父目录：

```text
/data/项目2_BH_dxf/
/data/项目2_BOX_dxf/
/data/项目2_PL_dxf/
/data/项目2_待确认_dxf/
/data/项目2_无法读取_dxf/
/data/项目2_分类清单.csv
/data/项目2_分类报告.json
```

只创建实际用到的类型目录。源文件保持不变。输出目录由 staging 一次性构造；默认拒绝覆盖已有输出，显式 `--overwrite` 才替换本工具拥有的同项目输出。替换前完成全部复制和 manifest 校验，失败时不提升半成品。

## 3. DXF 前端

读取层使用 ezdxf，并独立实现以下兼容逻辑：

- 先读取文档声明的 `$DWGCODEPAGE`；
- `GB2312`、`ANSI_936` 使用 Python `gbk` 重新读取；
- 保留读取失败的异常类型与消息；
- 遍历 modelspace 中的 `TEXT`、`MTEXT`、`ATTRIB`；
- 递归展开嵌套 `INSERT`，把块中文字变换到世界坐标；
- 每个文字事实保存文本、规范化文本、世界坐标、实体类型、图层、句柄和块路径。

规范化只统一 Unicode、全半角、空白、乘号和 ASCII 大小写，不删除具有工程意义的数字、连字符或型材前缀。

## 4. 标题栏识别与字段配对

识别不使用绝对坐标。先计算全部可见文字的包围范围，然后寻找标签集合：

```text
截面, 截面型材, 规格, PROFILE, SECTION, PROFILE/SIZE
```

标签必须位于图纸文字范围的上部或右部候选区域。对每个标签，按文字高度归一化距离，分别评估下方同列、右侧同行和表格相邻单元格中的值。候选值必须满足型材规格语法，且不能是字段标签、材质、比例、纯长度或说明句。

每个候选记录：标签事实、值事实、方向、归一化距离、区域位置和语法结果。唯一高质量候选才自动通过；同分、不同类型冲突、只有材料表命中或只有全图游离型材字符串时进入人工确认。

## 5. 类型解析

类型来自已配对截面值的前缀，而不是封闭的样本编号规则。规范化示例：

```text
BH1500*500*30*30  -> BH
box600×600×30×30  -> BOX
PL 20*300         -> PL
HN400*200*8*13    -> HN
RHS200*100*8      -> RHS
L90*8             -> L
```

内置注册表覆盖以下族，并保留具体前缀，不合并为大类：

- 板与扁钢：`PL`, `FB`；
- 焊接组合截面：`BH`, `BOX`, `BT`；
- H/I/T 型：`H`, `HW`, `HM`, `HN`, `HEA`, `HEB`, `HEM`, `I`, `IPE`, `IPN`, `UB`, `UC`, `T`；
- 角钢与槽钢：`L`, `C`, `CH`, `PFC`, `U`, `Z`；
- 空心截面与管材：`RHS`, `SHS`, `CHS`, `PIPE`；
- 棒材：`RB`, `SB`。

标题栏强配对且满足“字母前缀 + 尺寸主体”的未注册前缀可按原前缀分类，但报告标记 `catalog_status=unregistered`。纯数字规格、危险路径字符、中文说明词或无法形成稳定前缀的值不得动态建目录，进入待确认。

## 6. 决策与诊断

每个输入只允许三种处置：

- `classified`：标题栏字段唯一、类型一致、输出目录名安全；
- `review_required`：文档可读，但标题栏缺失、候选冲突或规格不完整；
- `unreadable`：文件不是有效 DXF、解码失败或遍历失败。

报告保存稳定诊断码，例如 `TITLE_FIELD_MISSING`、`TITLE_VALUE_CONFLICT`、`PROFILE_PREFIX_MISSING`、`DXF_READ_FAILED`。不使用模糊“置信度百分比”掩盖缺证据；报告保存实际证据和失败原因。

## 7. 模块边界

```text
src/steel_dxf_classifier/
  model.py       领域数据结构与处置枚举
  text.py        文本规范化
  reader.py      DXF 解码、INSERT 展开、文字事实
  title_block.py 标题栏候选和字段配对
  profile.py     规格语法、类型注册表和动态前缀
  classify.py    单文件证据决策
  batch.py       第一层枚举、复制、staging、manifest
  cli.py         参数解析和退出码
```

上层只依赖下层公开数据结构。`profile.py` 不读取 DXF；`reader.py` 不判断类型；`batch.py` 不重新解释工程证据。

## 8. 验证

测试分为：

- 单元测试：中文/全角规范化、前缀全集、危险目录名、空间配对和冲突；
- 合成 DXF：TEXT、MTEXT、ATTRIB、嵌套 INSERT、平移和不同比例图框；
- 真实语料：现有 BH 零件图只作为复制到新仓库测试夹具后的离线回归，不产生运行时依赖；
- 批处理：第一层扫描、忽略子目录、中文路径、覆盖保护、原子提升、CSV/JSON 一致；
- 负例：材料表有多个 PL/BOX 但没有标题栏截面字段时必须待确认；损坏 DXF 必须进入无法读取。

发布门要求测试、静态编译、真实样本分类和 Git 清洁度全部通过。
