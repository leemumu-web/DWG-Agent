# 1.1 输入输出流契约设计

## 目标

将分类器发布为正式 1.1.0：命令行输入、文件系统输入/输出、标准输出、标准错误和退出码均具有可复核的稳定契约。默认命令仍适合技术人员阅读，同时提供不混入人类提示的 JSON 标准输出给自动化调用。

## 命令行流

`steel-dxf-classify <项目名称>_dxf` 保持中文摘要输出。`steel-dxf-classify --json <项目名称>_dxf` 仅向 stdout 写入一个 UTF-8 JSON 对象和一个换行，字段为：

```json
{
  "schema": "STEEL-DXF-CLI-1.1",
  "status": "completed",
  "exit_code": 0,
  "summary": {}
}
```

当存在待确认或无法读取文件时，`status` 为 `completed_with_review`、`exit_code` 为 2，仍输出完整 JSON。运行时失败时 stdout 为空，stderr 仅写 `错误: <原因>`，退出码 1。命令参数/输入目录契约错误使用退出码 64，避免和完成但需人工审核的 2 混淆。`--version` 输出 `steel-dxf-classifier 1.1.0` 并退出 0。

## 文件系统流

输入只接受名为 `<项目名称>_dxf` 的目录，且只扫描第一层 `.dxf` 文件。预处理阶段先在原地事务性规范为 `*_拆板前.dxf`；冲突或失败时不留下部分改名。成功后读取标题栏，按证据结果复制到同级 `<项目名称>_<类型>_dxf`，并写入 JSON/CSV 报告。输入 DXF 字节不重写，输出副本与预处理后输入逐字节一致。

已有输出默认阻止运行；`--overwrite` 仅替换该项目分类目录与报告，通过 staging 和备份事务提升。预处理发生在已有输出检查之后，故未指定覆盖时不会修改输入名。

## 版本与报告

包版本、`VERSION`、README、CLI `--version` 和文件报告 schema 同步为 1.1.0/1.1。报告保留审计字段，并明确其是文件系统输出的权威记录；CLI JSON 是其面向自动化调用的摘要投影。

## 验证

测试覆盖默认摘要、单 JSON stdout、审核退出码 2、运行错误 stderr/空 stdout、参数错误退出码 64、版本输出及报告 schema。发布前重新运行完整测试、编译和构建，并以两份真实项目验证 JSON 摘要与文件报告一致，最后重建三个 ZIP。
