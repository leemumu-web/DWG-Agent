# DXF 拆板前文件名预处理设计

## 目标

分类器在读取输入目录前，将第一层所有 DXF 原地规范为 `原文件名_拆板前.dxf`。预处理是分类流程的必经阶段，重复运行必须稳定，不递归处理子目录。

## 命名规则

- `A.dxf`、`A.DXF` 均变为 `A_拆板前.dxf`；
- 已精确以 `_拆板前.dxf` 结尾的文件保持不变；
- `_拆板前` 只追加一次；
- 非 DXF 和子目录不参与预处理；
- 分类结果、JSON、CSV 使用预处理后的文件名。

## 安全与事务

预处理先计算完整重命名计划，再对目标名称做 Unicode 大小写折叠后的唯一性检查。若两个源文件映射到同一目标，或目标被计划外文件占用，整批停止且不修改文件。

执行采用两阶段重命名：先把所有待处理文件改为同目录隐藏临时名，再提升为正式目标名。任一步失败都按逆序回滚；临时名使用不可冲突的随机标识。文件内容不重写，因此 DXF 字节保持不变。

## 分类流程

`classify_directory()` 在检查输入目录契约后、读取 DXF 列表前调用独立的预处理组件。预处理成功后才解析标题栏和构建 staging 输出。已有分类输出仍遵循默认拒绝覆盖及 `--overwrite` 事务规则。

## 现有真实数据迁移

只迁移 `validation_projects/项目1/项目1_dxf` 与 `validation_projects/项目2/项目2_dxf` 第一层。随后使用 `--overwrite` 重建分类目录和 JSON/CSV 报告。原始 ZIP、项目1备份目录、项目2 DWG 目录不修改。

迁移验收包括：输入数量不变、所有输入均以 `_拆板前.dxf` 结尾、内容哈希不变、分类数量与类型分布不变、输出和报告全部使用新名称。

## 文档与发布

README 和分类规则删除“输入永远只读”的旧表述，明确 DXF 内容保持不变但输入文件名会在分类前原地规范化。验证记录追加真实迁移结果。完成测试、编译和构建后，重新生成并校验完整项目 ZIP。
