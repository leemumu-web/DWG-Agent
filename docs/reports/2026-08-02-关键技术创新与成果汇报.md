## 一、汇报摘要

本项目已经从多个独立 CAD/Excel 工具，发展为一套具有明确生产血缘、自动分流、专业图形处理、Excel 数据深化、数据库统一管理、权限控制和人工兜底边界的钢结构生产数字化平台。

当前最重要的阶段成果，是已经打通至生产流程第五阶段：

```text
多个源 DWG + 一个源 Excel
  → 服务器统一生成并冻结规范 DXF
  → DXF 自动识别、分类和分流
  → BH/BOX 自动拆板及独立校验
  → Excel 第一阶段自动整理
  → 读取拆板前 BH 图纸的左右进
  → Excel 第二阶段自动深化
  → 人工确认深化设计完整性
```

其中，DWG 只出现在最前端的源文件接收和留档环节；从服务器派生 DXF 开始，分类、拆板、左右进读取和后续图纸链路均使用 DXF。这一边界已经在输入冻结、文件登记和工作流合同中固化。

项目的核心创新可以概括为四点：

1. **从“文件工具”升级为“可追溯生产链”**：每一次输入、分类、拆板、Excel 处理和余料操作都有项目、文件、Job、attempt、结果和审计关系，不再依赖本机目录和人工传文件。
2. **从“猜测型自动化”升级为“证据型自动化”**：分类必须有标题栏证据，拆板必须通过几何证明和独立重开校验，左右进必须通过单位、主视图和实体板件证明；无法证明时转入人工处理，不制造虚假确定性。
3. **从“单点算法”升级为“跨专业数据闭环”**：图纸识别结果不只生成报告，还会转化为 Excel 中可复算的左进、右进、下料长度、理论重量和 `part` 下料数据，并同步进入数据库查询体系。
4. **从“个人台账”升级为“统一经营数据”**：MySQL 管理生产事实和业务关系，MinIO/本地对象存储管理大文件字节，权限和审计统一生效；余料也从散落 Excel 和图纸转成全厂共享库存状态机。

但必须明确：当前闭环止于“深化设计完整性屏障”。CAM 工作包生成、Windows SinoCAM 自动排版、CAM 结果接纳和最终交付归档尚未形成完整生产能力；余料库也尚未与未来 CAM 排版结果自动联动。我们已经完成了高质量的生产前半程，不应把它描述成整厂无人化排版闭环。

## 三、关键技术一：拆板前的全自动分流

### 3.1 解决的业务问题

传统流程中，图纸经常依赖文件名、人工建文件夹或操作者经验判断类型。问题不是“多点几下鼠标”，而是分类依据不可追溯、错分后仍可能进入下游、不同人员的目录结构不一致。

平台现在把这一环节拆成三个确定步骤：

1. 操作员上传一个源 Excel 和一个 DWG 文件夹；单次输入合同最多支持 5,000 张图纸。
2. 服务端逐张把 DWG 转为 DXF，重新检查对象大小、SHA-256、可读性和同名配对，然后冻结输入清单。源 DWG 保留为来源证据，后续使用服务器生成的规范 DXF。
3. Steel DXF Classifier 1.2.0 从 DXF 右上信息表的“截面/规格”字段建立证据，按 BH、BOX、PL、PX、RHS 等具体类型分流。

### 3.2 我们取得的创新

**第一，分类依据从文件名猜测变成标题栏语义证明。**

分类器支持 `TEXT`、`MTEXT`、`ATTRIB`、嵌套块和常见中文编码。它要求“截面/规格/PROFILE/SECTION”等标签与相邻值形成唯一证据。材料表中即使出现大量 `PL`、`BOX`、`BH` 字样，也不能越过标题栏证据直接分类。

**第二，对长尾类型既开放又克制。**

系统内置常见钢结构前缀，同时允许安全自动发现 2—12 个英文字母加数值尺寸主体的新类型，例如 `TT25`。自动发现会保留原具体前缀并标记 `type_source=auto_discovered`，而不是粗暴归到“其他”。未知单字母、材质牌号、螺栓规格、比例或不安全文本不会成为类型。

**第三，分类结果直接成为下游可执行合同。**

每张图在 MySQL 中保存原始规格、规范规格、类型来源、稳定分组键、诊断和 `next_stage_eligible`。只有证据充分的图纸可进入自动拆板；“待确认”和“无法读取”虽然保留完整报告，但不会被伪装成成功输入。

**第四，分流不破坏来源。**

分类只在临时副本上规范 `_拆板前.dxf` 文件名，冻结在对象存储中的规范源 DXF 不被改写。分类输出、JSON 审计报告和 CSV 清单分别登记；面向生产人员的目录与 ZIP 只展示 DXF，内部审计文件不混入交付包。

### 3.3 已记录的效率与规模证据

[Classifier 1.2.0 发布验证记录](../../Stages/steel_dxf_classifier_v1.1.0/docs/VALIDATION.md)保存了两组真实 Tekla 项目数据：

| 项目 | 输入 | 自动分类 | 待确认/无法读取 | 类型分布 | 实测耗时 | 吞吐 |
|---|---:|---:|---:|---|---:|---:|
| 项目 1 | 72 | 72 | 0/0 | BH 67、BOX 2、PL 3 | 15.155 秒 | 约 4.75 张/秒 |
| 项目 2 | 171 | 171 | 0/0 | BH 141、BOX 30 | 43.265 秒 | 约 3.95 张/秒 |
| 合计 | 243 | 243 | 0/0 | BH 208、BOX 32、PL 3 | 58.420 秒 | 约 4.16 张/秒 |

243 张图逐文件二进制对比均无字节变化。这个数字证明的是既有真实语料上的分类效率，不等于所有新项目都能 100% 自动通过；PX 和动态新类型在这两组真实项目中没有实物图，只由构造样本验证，不能冒充真实项目验收。

## 四、关键技术二：BH 和 BOX 自动拆板

### 4.1 从“分类”到“制造语义编译”

自动拆板不是简单把 DXF 图元复制到新图层。平台中的 Steel DXF Split 1.5.2 把图纸理解为制造对象：识别视图、腹板、翼板、轮廓、孔洞和板件关系，再生成可交付 DXF。分类和拆板职责严格分开，拆板直接消费上游冻结的 `part_type`，不在内部重复猜类型。

BH 与 BOX 使用两个独立领域核心：

- BH 面对腹板、上/下翼板、变截面、坡口、斜腹板、孔洞和板件关联等语义；
- BOX 是四板件问题，不能套用 BH 的三板逻辑，使用独立的腹板/翼板求解、制造 IR、投影和验证流程。

### 4.2 我们取得的创新

**第一，一次拆板同时生成两套完整制造产物。**

每张自动通过的输入严格形成：

- `normal`：正常拆板和孔洞处理后的完整 DXF；
- `weld_allowance`：从同一正常结果复制后，仅按允许规则移动板端，形成余量增长 DXF。

两份文件必须同源、同时验收、同时发布。任一份失败，该图纸就不能进入自动接纳。

**第二，把“算法说成功”升级为独立证据校验。**

算法子进程结束后，平台第二次独立打开普通版和余量版，检查 DXF 版本、毫米单位、实体和图层数量、孔洞几何与颜色、余量公式、报告绑定、目录隔离和成对完整性。正式下载 ZIP 只含已经通过校验的 DXF，报告和内部台账不混入生产文件。

**第三，把几何语义、制造规则和交付安全统一起来。**

例如对称圆孔不是按全图坐标粗略染色，而是在每块板件自己的局部 X 范围内寻找唯一镜像孔对，左孔显式红色、右孔显式白色；歧义孔保持白色。余量允许为 0，但必须由规则明确算出并写入报告，不能把“没有变化”误当作漏处理。

**第四，支持整批部分成功。**

每 30 张和最后尾批做数量守恒校验。单图无法证明时保留原图和原因，其他图纸继续处理；只要至少存在一组完整正式产物，工作流可以形成 `completed_with_review` 并把可靠结果交给 Excel。这样既避免“一张坏图拖垮整批”，也避免把失败图混进正式结果。

### 4.3 已记录的真实认证证据

- BH 发布能力文件绑定了 20 张来源图，`auto_accept=20`、`review_required=0`、`rejected=0`，并记录来源集合 SHA-256、编译器版本和本体版本。
- BOX 发布认证包含 20 对权威前后样例，其中 10 对用于校准、10 对用于独立验收；认证同时固定核心版本、commit 和实现指纹。
- 两个领域合计形成 40 张来源图的 40 组正式配对结果。这里的“一组”指普通版和余量版两份 DXF，不是只生成一个文件。
- BH 真实样例中已有 48 个圆孔的对称染色证据：24 个左孔为红色、24 个右孔为白色；BOX 当前权威真实样例没有同类镜像孔，因此 BOX 该规则仍以制造 IR 合成证据为主。

### 4.4 实现边界

- 自动拆板当前只覆盖有正式领域核心和发布证据的 BH、BOX；PL 和其他类型保留分类结果，不进入这两个核心。
- 无法形成几何证明的 BH/BOX 不进入正式 ZIP 或 Excel 交接。目前前端没有完整的逐图人工拆板回流工作台，主要通过分类原图、失败类别 ZIP 和诊断支持线下处理。
- 仓库中的运行时切片不包含上游全部 DXF 语料和算法级测试；BOX 黄金样本仍在外部只读目录，发布时必须继续进行上游认证。
- 通用 `.env.example` 默认关闭拆板开关，服务器部署模板默认打开；是否上线仍取决于真实项目验收和运维条件。

## 五、关键技术三：BH 左右进识别

### 5.1 业务价值

BH 下料不能只知道构件总长。腹板、上翼和下翼在左右端可能有不同退进量，直接影响各板件的下料长度。过去这一信息通常依赖人工量图、抄表和再次录入 Excel，工作重复且容易发生板件角色错配。

### 5.2 我们取得的创新

**第一，建立了符合生产习惯的几何口径。**

读取器先定位主视图，再识别腹板、上翼和下翼，最后在全局水平 X 方向读取左右进：

```text
左进 = 板件最左 X - 主视图最左 X
右进 = 主视图最右 X - 板件最右 X
```

程序不旋转构件，也不沿斜边测距。斜切、坡口和圆弧使用实体轮廓在全局 X 上的真实最外包络，避免把图形视觉长度误当作水平下料长度。

**第二，从“线段识别”提升到“实体板件归属”。**

内部竖线、焊缝线、腹板投影和加劲板边线不会把翼板误切成多块；只有翼板材料真实断开才形成多段。腹板端边必须经过净高、陡度和端部窗口检查，不能把长斜翼缘边当成腹板端点。

**第三，单位与数值安全优先于覆盖率。**

系统联合 `$INSUNITS`、BH 截面尺寸和标题栏名义长度判断毫米单位；标题栏 `1:10`、`1:20` 只代表显示比例，不参与模型坐标换算。单位、圆弧变换或材料层实体无法完整解释时，读取器拒绝输出。最终左右进严格向下取整，避免因浮点数或四舍五入导致下料偏短。

**第四，提供双解析后端和可视化诊断。**

正常优先使用 ezdxf，失败时回退内置 ASCII DXF 解析器；两条路径都处理线、多段线和 bulge 圆弧。输出包含 Excel、JSON 和校验图能力，便于技术人员回看主视图、板件角色、单位和左右进标注。

### 5.3 已保存的历史规模证据

[BH 左右进读取器说明](../../Stages/bh_left_right_reader/README.md)记录了三批共 199 张真实 DXF 的正式回归：

- ezdxf 与 ASCII 两条入口均为 199/199 `OK`；
- 共形成 420 条板件结果；
- 199/199 单位验证为毫米；
- 非有限数值 0 次、缺失板件证据 0 次；
- 发布记录包含 80 项自动检查和 432 个确定性有效 BH 组合。

这些是已有发布记录，不是本次调研重新跑出的数据。仓库未保存这 199 张图的整批墙钟耗时，因此不能据此虚构“节省多少小时”；可以确认的是，系统已经把 199 张图、420 个板件的重复量取工作转化为批处理能力。

### 5.4 实现边界

- 读取器服务于符合当前 Tekla/BH 图纸合同的 BH 构件，不是通用 CAD 测量器。
- 几何信息不足时采取安全拒绝或保守齐平，不外推大进尺。
- 当前 Excel 第二阶段只使用 BH 左右进；BOX 和其他截面没有同等的左右进深化合同。

## 六、关键技术四：Excel 自动处理第一阶段

### 6.1 形成统一、可审计的 Excel 生产入口

Excel Final 已经不是“清理几列、复制几个公式”的脚本，而是一个规范化数据产品。它自动识别标准 Tekla 工作簿、旧版二进制工作簿、DWG 初始表、制表符文本和固定宽度 Tekla 文本，之后统一进入同一套分类、手册查询、重量核验、BH/BOX/BT 子板拆分、`part` 汇总和写表引擎。

固定输出六张表：

1. `原表`：保留输入值、样式和原始空格；
2. `清洗表`：形成不可变父零件记录和规范分类；
3. `构件表`：形成构件级身份及重量/尺寸小计；
4. `整理表`：形成父件或 BH/BOX/BT 子板、重量链和可复算公式；
5. `part`：形成固定 12 列的未分班组下料投影；
6. `处理报告`：只保留警告、严重和致命的人工处置项。

### 6.2 我们取得的创新

**第一，源数据保留与业务加工分层。**

系统不在原表上原地清洗，而是保留原表并构造规范工作表。这样既能追溯输入，又能让算法升级后重新生成结果。

**第二，钢结构型材解析和子板语义统一。**

BH、BOX、BT 使用统一的制造型材解析器和“腹/翼”术语。BOX 不再沿用不稳定的 `BOX盖` 叫法，也不能回退成 BH。BH/BOX/BT 子板保留构件身份，普通板材和扁钢则按完整属性键跨构件汇总，避免仅按零件号错误合并。

**第三，重量计算从静态填值变成可核验链。**

板材密度使用 7.85；标准型材查统一五金手册数据库；圆管按确定公式计算；查无、冲突、跳过分别表达。系统同时检查单重×数量、总重×构件数、净重与理论重、理论重与毛重等物理关系，并把问题聚合成可执行报告。

**第四，Excel 公式与数据库精度同时保证。**

最终工作簿保留可见公式，并写入可立即读取的 OOXML 缓存；数据库使用 `DECIMAL(24,9)` 保存尺寸、数量、面积、比重和重量，避免大批量 `FLOAT` 累计误差。

**第五，唯一五金手册数据源进入数据库治理。**

五金手册源文件按 Sheet 和行号映射为可追溯关系表，部署使用单一 `hardware_handbook` schema。重复键但重量不同会返回 `conflict` 并要求修正来源，不使用 `LIMIT 1` 随机取一条。

|---|---:|---:|---:|---|
| 首都体育学院 B7 地下部分 | 527 | 122 | 3,637 | `无` |
| 003 郑州宝冶 | 7,399 | 3,017 | 53,796 | 7 条警告、1 条严重 |

B7 样本中，485 条父零件形成 527 条整理数据，其中 42 个 BOX 各增加腹/翼子板投影；项目净重为 122,013.557 kg、理论毛坯重 124,507.840 kg、表毛重 124,831.881 kg，满足净重≤理论毛坯重≤表毛重。该样本与 22 条已确认规则对比为 0 失败。

003 样本不是“强行全绿”，而是把真实问题暴露出来：包括 BH/BOX 几何理论重偏差、标准型材手册偏差、净重大于理论重，以及 1 条严重的源重量链异常。这体现了系统的价值不仅是提速，还包括把原来藏在表格里的数据问题显性化。

仓库没有为这两份结果保存可复核的单次处理墙钟时间，因此本报告只陈述数据规模和自动动作，不估算人工节省比例。

### 6.4 实现边界

- 第一阶段处理的是一个冻结源 Excel，不是从 DXF 自动生成 Excel；独立的 DXF→Excel 工具不属于生产主流程。
- 工作流要求先形成正式拆板交接或明确“无需拆板”，第一阶段才可执行；当前第一阶段算法本身仍以源 Excel 为业务输入，拆板交接主要承担血缘和就绪屏障，并不直接把拆板 DXF 几何写入表格。
- 五金手册 MySQL 是正式依赖，数据库不可用时处理必须失败，不能静默回退到不受控常量。

## 七、关键技术五：Excel 自动处理第二阶段及识别结果集成

### 7.1 为什么必须分两阶段

第一阶段解决“源清单规范化、型材拆分、重量和 `part` 基线”；第二阶段解决“把图纸上的真实 BH 左右进反映到每块板的下料长度”。两阶段分开后，既能保留稳定的 Excel 基线，也能明确区分清单问题和图纸识别问题。

第二阶段读取的不是拆板后板件 DXF，而是分类阶段冻结的**拆板前 BH 构件图**。原因是左右进需要完整主视图和腹板/翼板相对构件端部的位置；拆板后的单板图已经失去这层构件上下文。这是数据血缘设计中的重要进步。

### 7.2 集成闭环

1. 服务端验证当前成功的第一阶段 Excel、当前分类 Job/attempt、BH 文件清单、对象 SHA-256 和工作流项目归属。
2. BH Reader 批量读取拆板前 BH 图，生成 `BH左右进读取表.xlsx` 和版本化内部测量合同 `bh_setback_measurements/v1`。
3. Excel Stage 2 从正式第一阶段工作簿重建基线，证明六表、表头、公式和缓存未漂移。
4. 对每个 BH，核对分类账规格、Reader 规格、Excel 规格三方一致；同时核对腹板、上/下翼板角色完整。
5. 对每块板计算：`下料长度 = 原模型长度 - 左进 - 右进`，并重新计算总长、理论单重、理论总重、数量和 `part`。
6. 左右进读取表、第二阶段正式 Excel、关系化零件/构件投影、质量状态和统计同时登记。

### 7.3 我们取得的创新

**第一，识别结果不再停留在报告，而是进入业务数据。**

左进、右进和下料长度进入 `整理表` 与 `part` 的同一物理身份，数据库中也能按批次、零件、构件和类型查询。这完成了“图纸几何识别→生产清单”的关键跨域集成。

**第二，采用三方一致而不是单源覆盖。**

分类、Reader 和 Excel 任一规格不一致，系统都不会自动套用左右进。这样可以防止同名图、错版本图或 Excel 规格漂移把正确测量写到错误零件上。

**第三，失败时保持业务可继续且不伪造数据。**

- 项目没有 BH：第二阶段仍生成与第一阶段一致的正式结果，状态为 `noop`；
- Excel 有 BH 但缺图：保留第一阶段原长度并产生告警；
- 图纸存在但读取/匹配不可靠：左右进和下料长度留空，转人工补录；
- 图纸在分类账存在但 Excel 中无对应零件：记录“BH 图纸未进入 Excel”告警。

**第四，结果发布具有 attempt 和文件血缘保护。**

旧任务、旧分类批次、旧第一阶段文件或对象摘要变化均不能覆盖当前正式结果。读取表和正式 Excel 分开登记，诊断表不能被误当作完成结果。

### 7.4 实现边界

- 当前第二阶段只处理 BH 左右进，不是所有截面、所有板件几何的通用深化器。
- 第二阶段同步深化 `整理表` 和 `part`，但不代表已经形成跨全部图纸的数据库级生产屏障、CAM 工作包或排版汇总。
- 最大 BH 输入合同为 5,000 张、专用 worker 并发为 1，目标是控制内存、数据库查询和发布次序；仓库没有保存 5,000 张真实图的墙钟耗时，不能把容量上限写成已验证吞吐。

## 八、关键技术六：余料库集成与统一管理

### 8.1 从散落图纸和 Excel 转为全厂共享库存

余料模块已经形成独立业务域，不再把余料当作某个项目目录里的附件。它拥有材质目录、导入批次、导入项、正式余料、多个零件编号、状态流转、查询、导出和审计。

正式库存状态为：

```text
可用 → 已预占 → 已使用
  └→ 已归档 → 删除库存记录
```

预占采用数据库条件更新，同一张余料并发请求只能有一人成功。只有预占人或管理员可以释放或标记使用；删除只允许作用于已归档记录，并保留原图、导入账本和删除前快照。

### 8.2 两种导入模式

**普通批量导入**适用于格式不统一的 DWG/DXF。DWG 先转为解析用 DXF，系统提取材质、项目和多个零件号候选，工人确认厚度、材质、项目编号、库位和备注后入库。单图失败不阻塞同批其他图纸。

**标准块自动导入**适用于含唯一 `offcut_zh_cn` 块的图纸：

- `GG`：厚度×长×宽；
- `CZ`：完整材质牌号；
- `YLBH`：余料或零件编号。

属性完整且合法时自动填充；缺块、重复块、属性缺失或规格非法时明确告警，不从文件名和普通文字猜测正式字段。

### 8.3 统一管理带来的优势

1. **库存从“找文件”变成“查数据”**：可按材质、厚度、同系列、状态、两个项目编号、库位、两个备注和零件编号筛选。
2. **材质从自由文本变成受控目录**：自动识别新牌号时可建档，停用材质可恢复并审计；历史引用不因删除材质而断裂。
3. **原图、预览和业务记录各司其职**：原始 DWG/DXF 由文件系统统一授权，转换 DXF 只用于解析和预览，库存表只保存业务关系。
4. **支持批量但允许部分成功**：自动导入单批最多 100 张；批量归档一次最多 200 条，每条用保存点隔离失败，合法记录不因个别问题回滚。
5. **形成可交接的全局 Excel**：导出一张余料一行的工作簿，并对以 `=、+、-、@` 开头的文本做公式注入防护。
6. **刷新和换人后仍能恢复进度**：导入批次、attempt 和待确认项保存在数据库，不依赖某个浏览器页面一直打开。

### 8.4 已知容量和运行设计

- 单批导入上限：100 张；
- 余料转换队列默认并发：2；
- 余料解析队列默认并发：4；
- 单张解析默认超时：120 秒；
- 批量归档上限：200 条。

这些是设计容量和并发配置，不是现场实测吞吐。仓库内当前只看到一份真实余料 DWG 和一份历史余料 Excel，且没有保存本次可引用的完整转换/解析效率报告，因此正式扩大使用前仍需在隔离环境重放真实样本。

### 8.5 实现边界与文档修正项

- 余料库目前是独立的导入、确认、共享和状态管理系统，尚未从 CAM 排版结果自动计算并入库余料，也没有自动把预占余料回送给排版算法。
- 通用环境模板默认关闭余料库，服务器部署模板默认打开；生产开启仍要求材质、权限、备份、恢复和真实样本验收。
- 当前代码允许 `operator/admin/super_admin` 使用余料能力，只有 `admin/super_admin` 管理材质；旧使用说明中出现的 `remnant_worker` 已与当前角色模型不一致，文档需要同步。

## 九、数据库集成统一管理的创新与优势

### 9.1 当前数据底座

当前运行时机器合同记录：

- 48 张 SQLAlchemy ORM 应用表；
- 183 条 HTTP 路径、211 个操作；
- 16 个 Celery 任务、14 条任务路由；
- 当前 Alembic 唯一 head：`e6b1f9a2c470`。

与本次汇报直接相关的数据域包括：

| 数据域 | 核心账本 |
|---|---|
| 文件与对象 | `files`、`file_transfers`、存储扫描与异常账本 |
| 异步任务 | `jobs`、`job_dispatches`、`job_steps`、`analysis_results`、`review_records` |
| 生产工作流 | 输入批次/条目、workflow/stage、artifact、分批导出、完整留存 |
| DXF 分类 | 分类 run 和逐图 item |
| DXF 拆板 | 拆板 run、逐图 item、复核决定 |
| Excel | batch、part、component 三张关系投影 |
| 余料 | 材质、别名、导入批次、导入项、余料、余料零件六张表 |
| 身份权限 | 用户、角色、权限、关联表、token blacklist |

文件字节不放进 MySQL。MySQL 保存业务事实、对象位置、大小、SHA-256、项目和处理关系；DWG、DXF、Excel、报告和 ZIP 成员字节放在 Local/MinIO。这样避免大文件拖垮事务数据库，同时保留可查询关系。

### 9.2 对公司管理的直接价值

**第一，建立唯一生产事实源。**

过去“哪个文件夹是最新”“这份 Excel 对应哪批图”“这张图是否已经拆板”依赖人员记忆。现在可以通过 workflow、stage、Job attempt、file/result ID 和 manifest SHA-256 回答，不需要从文件名推断。

**第二，形成端到端血缘。**

一张源 DWG 可以追到服务器派生 DXF、分类输出、拆板普通版/余量版、Excel 阶段结果和下载流水；一行 Excel 数据可以追到批次、构件、零件和质量状态。错误定位从“翻目录”变成“查账本”。

**第三，支持跨人员接续生产。**

生产产物归项目和工作流，不归某个上传者私有。只要是有权限的项目成员，后续工程师可以接续前一位人员生成的服务器产物，减少人员变动和交接风险。

**第四，保证重试和并发安全。**

Job 的 claim、进度、结果和失败都同时校验 status＋attempt，旧 worker 不能覆盖新一轮结果。每个新 attempt 与 `job_dispatches` 在同一事务落库，再由带 lease 的 dispatcher 投递；即使消息重复，稳定任务 ID 和 attempt 门禁也能避免业务副作用重复生效。

**第五，支持部分成功和人工处理。**

分类、拆板、Excel 和余料都能保存逐项状态，不再只有“整个目录成功/失败”两个结果。管理者可以知道自动通过多少、需要人工多少、失败原因是什么。

**第六，数据可用于经营和质量分析。**

Excel 零件/构件、重量状态、分类类型、拆板处置、余料材质和库存状态已经是关系化数据，可以做项目统计、质量趋势、库存利用和生产效率分析，而不是先人工整理 Excel 才能统计。

**第七，存储治理更可控。**

文件传输有 durable saga；数据库与对象存储无法共享单一 ACID 事务时，系统明确记录 pending、成功、失败和补偿状态。完整备份成功且再次确认后才允许整批释放对象，并保留业务关系和审计证据。

### 9.3 当前边界

- 当前 Celery broker 仍是 MySQL SQLAlchemy transport，不是目标架构中的 RabbitMQ。事务 outbox 已解决应用提交与消息投递的主要双写窗口，但不宣称 broker exactly-once。
- SSE 只保存最新状态快照，不能回放完整编号事件历史。
- 本次调研时本机 Compose 服务未运行，因此本文陈述的是当前代码与已保存产物，不把数据库写成“此刻在线生产状态”。
- MySQL 与对象存储仍需联合备份和恢复演练；只备份其中一方不能恢复完整生产事实。

## 十、权限管理系统的优势与边界

### 10.1 双层权限模型

平台不是只在前端隐藏按钮，而是由 FastAPI 和领域服务执行授权。权限分两层：

**全局角色：**

- `super_admin`：唯一、受保护的权限根；不能被禁用、删除、降级或由他人重置；
- `admin`：与超级管理员具有相同业务管理和数据可见能力，但不能授予第二个超级管理员；
- `operator`：可以执行生产工作流、文件、任务、复核和余料操作，不能管理用户和角色；
- `viewer`：只读查看已授权项目、流程和结果。

从实际权限效果看是“管理员、操作员、只读”三级，`super_admin` 额外承担唯一恢复根职责。

**项目角色：**

- `project_owner`、`project_engineer` 可执行项目和工作流写操作；
- `project_owner`、`project_reviewer` 可执行结果复核；
- 其他项目成员按成员资格获得读取范围；
- 管理员拥有全局项目访问能力。

### 10.2 权限系统带来的优势

1. **业务权限跟随项目，而不是跟随文件上传人**：同项目工程师可以接续工作流，但非项目成员无法通过猜 ID 读取文件或结果。
2. **文件、Job、Result 权限继承一致**：文件与 Drawing/Result/Project 的关系决定可见范围；Result 复核复用 Job 和项目角色，不另开后门。
3. **下载不是拿到链接就能访问**：签名路径仍要求有效登录和文件权限；签名 300 秒过期，不在 URL 放 access token。
4. **危险操作增加二次门槛**：整批永久清理要求管理员、已成功完整下载、当前范围复检和精确确认词，避免误操作。
5. **唯一超级管理员受系统不变量保护**：启动会修复配置账号的受保护角色，历史多余超级管理员会归一为普通管理员，避免多个不可控权限根。
6. **关键变更形成审计**：用户、角色、文件、任务、复核、Excel 和余料操作写入审计日志，便于责任追溯。

### 10.3 当前边界与需要继续完善的点

- 当前三种权限种子较粗，实际细粒度主要由各路由和项目角色规则实现；未来扩大跨部门使用时，应继续把关键领域动作沉淀为明确权限合同。
- 前端权限守卫只改善交互，不能替代后端授权；这一点当前实现正确，但后续功能必须继续遵守。
- 审计表不是密码学不可变、数据库强制 append-only 或 WORM 存储。高权限数据库/应用泄露仍可能改写审计，高保证部署需要外部只追加导出和独立访问控制。
- 当前 Compose 浏览器入口仍是 HTTP，公网或不可信网络上线前必须补 TLS、Secure cookie 和网络入口限制。
- 余料旧文档中的 `remnant_worker` 角色名需要改为当前的 `operator` 口径。

这一口径有意区分“实测速度”“真实样本规模”“设计容量”。对领导汇报时，应重点讲已经消除的重复动作和错误点，不应在没有人工基线的情况下给出虚假的节省百分比。

## 十二、我们真正形成的创新成果

### 12.1 技术创新

1. **标题栏证据驱动的钢结构 DXF 分类**，并把长尾类型安全自动发现与下游资格合并到同一合同。
2. **BH/BOX 双领域制造语义编译**，避免用一个通用几何脚本硬套不同截面逻辑。
3. **正常版＋余量版成对生成、独立重开校验**，把加工结果可靠性作为产品功能，而不是测试附属品。
4. **BH 实体板件左右进算法**，同时处理主视图、单位、斜端、圆弧、多翼板和安全取整。
5. **图纸识别与 Excel 二阶段融合**，以分类、Reader、Excel 三方一致保护业务写入。
6. **固定六表、公式缓存、物理重量链与关系数据库投影**，同时服务现场使用和管理分析。
7. **attempt＋事务 outbox＋对象传输补偿**，使长耗时 CAD 任务具备可重试和可恢复基础。

### 12.2 产品与管理创新

1. 把自动化的成功、待确认、无法读取、部分成功和严重数据问题变成可见状态，而不是只给一个“处理完成”。
2. 把生产结果归属到项目和工作流，使不同人员能够安全接续。
3. 把余料从个人 Excel 台账变成共享库存，并用状态机控制预占、领用和归档。
4. 把权限、审计、下载、备份和删除门槛纳入同一产品，避免算法上线后再补治理。
5. 建立了“自动处理到证据边界，超出边界转人工”的务实路线，既提高效率，也控制生产风险。

## 十三、必须向领导说明的实现边界

1. **完整生产线尚未闭环。** 当前已做到 Excel 第二阶段；深化设计完整性仍需人工确认，CAM 打包、Windows SinoCAM、结果接纳和最终交付尚未实现。
2. **自动拆板只覆盖 BH/BOX。** PL 和其他类型已能分类、导出和人工处理，但没有统一自动拆板核心。
3. **缺少完整人工拆板回流工作台。** 当前有失败分类、原图 ZIP 和诊断证据，但没有把人工下载、处理、上传、校验、接纳做成完整状态机页面。
4. **Excel 第二阶段只深化 BH。** BOX 和其他截面的图纸识别结果尚未形成同类 Excel 合同。
5. **余料尚未与排版闭环。** 已经实现统一库存，但尚未从 CAM 自动生成余料，也未自动参与后续选料优化。
6. **效率证据仍不完整。** 分类有真实耗时；Excel、拆板、左右进和余料主要有规模/认证证据，缺现场人工基线和持续生产统计。
7. **生产启用受开关和环境约束。** 通用模板采取默认关闭，服务器模板开启核心能力；实际上线仍需要 MySQL、MinIO、Worker、Stage、手册库和真实样本同时通过。
8. **安全与运维仍需继续建设。** RabbitMQ、TLS、外部只追加审计、集中指标告警和 MySQL＋对象存储恢复演练仍是后续重点。
9. **少量文档存在历史漂移。** 例如余料角色名和较早实施状态已落后于当前代码，后续发布应以机器合同和当前模块 README 为准，并同步修正文档。

## 十四、对公司价值的判断

### 14.1 短期价值：减少重复操作和人为传递错误

- 自动完成 DWG→DXF、分类建目录、BH/BOX 拆板、左右进量取和 Excel 回填；
- 对缺图、错规格、重量异常和无法证明的几何给出明确问题清单；
- 同一批数据只登记一次，通过 ID 和清单在各阶段传递，减少重复上传和错版本。

### 14.2 中期价值：建立企业级工程数据资产

- 分类类型、零件/构件、重量质量、拆板处置、余料库存全部进入可查询数据库；
- 可以进一步形成项目效率、异常类型、自动通过率、材料利用率和库存周转报表；
- 算法版本、输入摘要和结果关系被保留，为后续规则迭代和责任追溯提供基础。

### 14.3 长期价值：为自动排版和智能决策提供可信输入

未来 CAM 和排版算法真正需要的不是一堆目录，而是已经被分类、拆板、校验、赋予零件身份并通过权限治理的数据。本项目已经把这一前置基础建成。后续接入 SinoCAM、余料优选和生产计划时，可以复用现有文件、Job、workflow、数据库和权限体系，而不必重新建设一套数据底座。

## 十五、建议的领导汇报表述

建议用以下三句话概括：

> 第一，我们已经把钢结构生产前半程从多个独立工具整合成一条可追溯的自动生产链，完成了自动分流、BH/BOX 拆板、BH 左右进和 Excel 两阶段处理。
> 第二，我们的创新不只追求自动率，而是要求每个自动结果都有标题栏、几何、单位、版本和数据库血缘证据；不能证明的图纸明确转人工，保证生产安全。
> 第三，MySQL、对象存储、权限、审计和余料库存已经形成企业级底座，下一阶段的重点是补齐人工回流、CAM/SinoCAM 和余料参与排版的后半程闭环。

如果需要一组最有说服力的数字，可使用：

- 243 张真实 DXF 自动分类，历史实测合计 58.420 秒；
- 199 张真实 BH 图形成 420 个板件左右进结果；
- BH 20 张自动接纳、BOX 20 对黄金样本认证；
- 单份 Excel 已观察到 7,399 条整理数据、3,017 条 `part`、53,796 个公式；
- 平台机器合同包含 48 张应用 ORM 表、183 条 HTTP 路径、211 个操作；
- 生产输入合同单批上限 5,000 张，余料单批上限 100 张。

必须同时补一句：前四组数字分别代表实测分类、历史发布回归、发布认证和现有产物规模，不能混成同一种“生产吞吐率”。
