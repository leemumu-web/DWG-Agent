我们建设的 CAD 智能生产平台，是一套贯穿生产资料接收、图纸转换、自动分流、BH 和 BOX 拆板、BH 左右进识别、Excel 两阶段加工、数据库沉淀、权限控制和余料管理的生产前置平台。系统解决的核心问题，不只是减少人工点击和重复录入，而是让每一份源文件、每一次处理、每一个结果和每一项异常都有来源、有状态、有责任人、有明确去向，把依赖个人经验和本机目录的工作方式，逐步转变为公司可管理、可追溯、可持续积累的数字化生产流程。

系统首先确立了清晰的数据源原则。生产入口接收一个源 Excel 和一批 DWG，DWG 作为原始依据保留，服务器统一派生后续使用的 DXF。分类、拆板、左右进读取和后续图纸流转全部使用服务器生成的 DXF，避免人工上传的 DWG 与 DXF 版本不一致。输入进入流程前还会检查文件可读性、同名关系、对象大小和 SHA-256，并形成冻结清单。这样，一张图从哪里来、转换成了什么、后续使用的是哪个版本，都可以重新核对。单批输入合同已经按最多 5,000 张图纸设计，具备承接大型项目的架构基础。

平台形成了“证据型自动化”的核心设计理念。系统不追求所有文件都显示自动成功，而是要求每一个自动结果都能说明依据。图纸分类必须找到标题栏中的截面或规格证据，拆板必须通过板件几何关系和独立重开校验，BH 左右进必须证明主视图、毫米单位和实体板件归属，Excel 第二阶段必须同时满足分类规格、读取规格和表格规格一致。证据不足时，系统保留原图、诊断和人工处理入口，不让不确定结果继续流入生产。这样的设计把自动化从“程序给出答案”提升为“系统对答案负责”。

拆板前的自动分流已经从依赖文件名和人工建目录，进步为基于图纸语义的自动识别。分类器读取 DXF 右上信息表中的截面、规格、PROFILE、SECTION 等字段，支持普通文字、多行文字、块属性、嵌套块和常见中文编码，可以识别 BH、BOX、PL、PX、RHS 等类型。对于企业自定义或低频型材，系统允许在安全规则内自动发现新的英文前缀和尺寸组合，同时拒绝把材质牌号、螺栓规格、比例或危险文本误判为构件类型。分类结果会把原始规格、规范规格、类型来源、分组、诊断和下游资格写入数据库，可靠图纸自动进入对应工序，待确认和无法读取图纸则被隔离处理。

自动分流已经形成真实项目效率证据。两组 Tekla 项目合计 243 张 DXF，在个人笔记本电脑上 58.420 秒内完成分类，平均约 4.16 张每秒，其中包括 208 张 BH、32 张 BOX 和 3 张 PL。243 张图逐文件进行二进制对比，分类前后没有发生字节变化。这说明系统已经能够在一分钟内完成数百张既有项目图纸的识别和分流，同时保留源文件完整性。该成绩证明的是现有真实语料上的处理能力，不把它扩大解释为所有新项目都必然百分之百自动通过。

BH 和 BOX 自动拆板采用了两个独立的制造语义核心，而不是用一套通用几何脚本强行覆盖不同构件。BH 重点处理腹板、上下翼板、变截面、斜腹板、坡口、孔洞和多段翼板关系；BOX 按四块板件的制造逻辑处理腹板、翼板、投影和轮廓。分类器负责确认图纸类型，拆板器直接使用上游已经冻结的类型，不在内部重新猜测，保证了专业边界清晰，也为后续分别升级 BH 和 BOX 算法保留空间。

每张自动通过的 BH 或 BOX 图纸都会形成正常拆板版和余量增长版两份完整 DXF。余量版从同一份已确认结果派生，只移动制造规则允许移动的板端。算法完成以后，平台会再次独立打开两份 DXF，核对版本、单位、实体、图层、孔洞、余量公式、报告绑定和成对完整性。两份文件必须同源、同时通过、同时发布，任何一份缺失或无法证明，都不能进入正式结果包。系统由此把“生成文件”提升为“交付经过独立验证的制造结果”。

拆板批处理支持部分成功，并对每 30 张图和最后尾批进行数量守恒检查。一张异常图不会拖住整个项目，但异常结果也不会混入正式 ZIP。可靠结果可以先进入后续 Excel，失败图保留原图和明确原因等待人工处理。现有发布证据中，BH 有 20 张来源图全部自动接纳，BOX 有 20 对权威前后样例完成校准和独立验收，两个领域核心都已经具备来源绑定、版本指纹和正式配对结果。BH 真实样例还形成了 48 个圆孔的对称识别证据，其中 24 个左孔标红、24 个右孔保留白色。

BH 左右进读取解决了构件总长无法直接代表各板下料长度的问题。系统先定位主视图，再识别腹板、上翼板和下翼板，最后按照全局水平 X 方向计算板件两端相对于构件两端的退进量。算法不旋转构件，不沿斜边测量视觉长度，斜切、坡口和圆弧统一回到实体轮廓的水平最外包络。内部竖线、焊缝线、腹板投影和加劲板边线不会被误认为板件端边，只有翼板材料真正断开时才形成多段翼板。

左右进读取把生产安全放在覆盖率之前。系统联合 DXF 单位、BH 截面尺寸和标题栏名义长度判断毫米单位，不把图纸比例当作模型坐标换算依据；单位、圆弧变换或实体归属无法证明时拒绝输出。最终左右进严格向下取整，避免浮点误差或四舍五入造成下料偏短。现有正式回归覆盖 199 张真实 BH 图，两条 DXF 解析路径均为 199 张全部通过，共形成 420 条板件结果，单位全部确认为毫米，没有出现非有限数值和板件证据缺失；发布记录还包含 80 项自动检查和 432 个确定性有效 BH 组合。这项能力已经把逐图量取转变为可批量执行、异常复核的专业工序。

Excel 自动处理采用两阶段设计。第一阶段负责把源清单整理成稳定、统一、可复算的数据底稿，第二阶段负责把 BH 图纸中识别出的真实左右进深化到下料数据。两阶段分开以后，清单规范化不会被一张异常图拖垮，图纸深化也不能绕过稳定基线直接覆盖表格；出现问题时能够明确区分是源 Excel、图纸缺失、规格不一致还是左右进读取失败。

Excel 第一阶段已经形成统一的生产入口，可以处理标准 Tekla 工作簿、旧版 Excel、DWG 初始表、制表符文本和固定宽度 Tekla 文本，并固定生成原表、清洗表、构件表、整理表、part 和处理报告六张表。原始数据得到保留，业务数据在独立工作表中规范化；BH、BOX、BT 等制造型材会展开为腹板和翼板，普通板材和标准型材按照统一规则分类和汇总。系统通过数据库中的唯一五金手册查询比重，来源相同而重量冲突时明确返回冲突，不随机取值；同时核对单重、数量、总重、构件数、净重、理论重和毛重之间的物理关系。最终工作簿保留可见公式和可立即读取的公式缓存，数据库则使用高精度十进制保存关键尺寸和重量，既方便现场复核，也支持后续统计分析。

Excel 第一阶段已经在真实工作簿中体现出数千行规模的自动处理能力。首都体育学院 B7 样本由 485 条父零件形成 527 条整理数据、122 条 part 数据和 3,637 个可复算公式，项目净重 122,013.557 千克、理论毛坯重 124,507.840 千克、表毛重 124,831.881 千克，与 22 条已确认规则对比为 0 失败；003 郑州宝冶样本形成 7,399 条整理数据、3,017 条 part 数据和 53,796 个公式。系统没有为了追求全绿而隐藏问题，而是在第二个样本中明确发现 7 条警告和 1 条严重源重量链异常。由此取得的成绩不仅是快速形成规范结果，更重要的是把原来可能埋藏在大表中的重量和数据质量问题提前暴露出来。

Excel 第二阶段完成了图纸识别结果向业务表格的真正集成。系统读取的是分类阶段冻结的拆板前 BH 构件图，因为左右进依赖完整主视图和各板件相对构件端部的位置，拆板后的单板图已经失去这层上下文。处理时同时核对分类账规格、BH Reader 规格和 Excel 规格，并检查腹板、上下翼板角色完整。三方一致后，系统按照下料长度等于原模型长度减去左进和右进进行计算，同时更新整理表、part、理论单重、理论总重和数据库中的零件、构件投影。

第二阶段对异常采用保守而可继续的处理方式。项目没有 BH 时，系统生成与第一阶段一致的正式结果；Excel 中有 BH 但缺少图纸时，保留原长度并给出告警；图纸存在但读取或规格匹配不可靠时，左右进和下料长度留空，交由人工补录；图纸存在但 Excel 中没有对应零件时，系统记录未进入 Excel 的问题。旧任务、旧分类批次、旧第一阶段文件或对象摘要发生变化时，均不能覆盖当前正式结果。这样既保证项目能够继续推进，又不通过默认值伪造生产数据。

数据库统一管理是整套系统从工具升级为平台的关键。当前运行时合同记录了 48 张应用 ORM 表、183 条 HTTP 路径和 211 个操作。MySQL 统一保存项目、文件登记、对象摘要、任务状态、工作流阶段、分类结论、拆板处置、Excel 零件和构件、余料库存、用户权限及审计关系；DWG、DXF、Excel、报告和 ZIP 等大文件字节由本地或 MinIO 对象存储管理。数据库负责业务事实和关系，对象存储负责大文件容量和交付，两者通过文件 ID、结果 ID、大小和 SHA-256 建立确定联系。

统一数据库让公司拥有明确的生产事实源。过去依赖个人记忆回答的“哪个目录最新”“这张图为什么没有拆板”“这份 Excel 对应哪批图”，现在可以通过工作流、阶段、任务 attempt、文件关系和清单摘要直接查询。一张源 DWG 可以追溯到派生 DXF、分类结果、拆板普通版和余量版、Excel 两阶段结果及下载记录；一行 Excel 数据可以追溯到批次、构件、零件和质量状态。不同人员可以围绕同一项目接续处理，问题定位从翻目录转变为查账本，后续也可以直接形成自动通过率、异常类型、项目周期、重量质量和余料周转等管理指标。

系统针对长耗时 CAD 任务建立了可恢复、可重试的任务机制。每次重试产生新的 attempt，旧 worker 不能覆盖新一轮结果；新任务和待投递记录在同一数据库事务中生成，再由带租约的调度器投递。数据库和对象存储无法共享单一事务时，文件传输流水会记录准备、成功、失败和补偿状态。这样的设计不宣称消息绝对只投递一次，而是通过稳定任务身份、处理代次和幂等门禁，保证重复投递不会重复生效，显著提高了批量生产任务的可恢复性。

权限系统采用全局角色与项目角色相结合的双层模型。全局设置超级管理员、管理员、操作员和只读用户，超级管理员作为唯一受保护的恢复根，不能被普通操作禁用、删除或降级；项目内部再由项目负责人、工程师和复核人承担执行和复核职责。文件、任务和结果的权限跟随项目关系，而不是只跟随最初上传人，同一项目的工程师可以安全接续，非项目成员不能通过猜测文件或结果编号越权访问。

权限控制落实在后端和领域服务中，不依赖前端隐藏按钮。下载链接即使带有短期签名，仍然需要有效登录和文件权限；永久清理要求管理员权限、完整备份下载、范围复检和明确确认。用户、角色、文件、任务、复核、Excel 和余料的关键操作都会留下审计记录。权限系统带来的价值不是增加操作门槛，而是让平台可以从小团队扩展到跨项目、跨岗位协作，同时保持数据边界、责任追溯和交接连续性。

余料库把过去分散在图纸、个人 Excel 和现场经验中的材料信息，转化为全厂可查询、可预占、可领用、可归档的共享库存。系统统一管理材质、厚度、长宽、项目编号、库位、备注、多个零件编号和原始图纸，现场人员可以按业务字段查找余料，不再依赖文件名和个人记忆。库存按照可用、已预占、已使用、已归档进行状态流转，数据库条件更新保证同一块余料在并发预占时只有一人成功，删除只允许作用于已归档库存记录，并保留原图、导入账本和审计快照。

余料导入兼顾历史资料和标准化未来。普通 DWG 或 DXF 可以先转换、解析候选字段，再由人员确认厚度、材质、项目和零件号；带唯一 offcut_zh_cn 标准块的图纸，则可以直接读取规格、材质和余料编号。块缺失、重复或属性非法时，系统明确提示人工处理，不从文件名或普通文字补猜正式字段。单批自动导入最多 100 张，转换和解析采用独立队列，单图失败不影响同批其他图纸；批量归档一次最多 200 条，并允许逐条返回结果。余料由此从个人台账变成了具有状态、权限和审计的公司材料资产。

系统取得的效率进步需要按照证据类型分别理解。自动分类已经有 243 张真实 DXF、58.420 秒的直接速度记录；BH 左右进已经有 199 张真实图、420 条板件结果的批量规模记录；BH 和 BOX 拆板已经分别有 20 张全自动接纳和 20 对权威样本认证；Excel 已经形成 7,399 条整理数据、3,017 条 part 和 53,796 个公式的真实结果规模。单批 5,000 张图纸、余料单批 100 张和批量归档 200 条属于设计容量。Excel、拆板、左右进和余料尚缺少持续现场墙钟数据和统一人工基线，因此现阶段不使用无法追溯的节省工时或效率提升百分比。

这套系统已经明确消除了大量重复且容易出错的操作。图纸不再逐张依靠人工判断类型和建立目录，可靠的 BH 和 BOX 不再逐张选择拆板程序，BH 左右进不再逐图量取和抄写，Excel 不再依靠个人公式和临时透视表维持，同一批资料不再在不同阶段反复上传和人工确认版本。一张异常图也不会让整个项目停住，缺图、规格冲突、重量异常、单位不确定和拆板结果不成对等问题会在进入下游前显性出现。系统带来的价值不仅是程序运行更快，更是减少错误传递、缩短问题定位和支持人员交接。

当前系统已经完成生产前半程的平台化闭环，覆盖源 Excel 和 DWG 接收、服务器派生 DXF、自动分类分流、BH 和 BOX 自动拆板、Excel 第一阶段、BH 左右进识别、Excel 第二阶段、数据库沉淀、权限审计和余料统一管理。自动拆板目前只覆盖 BH 和 BOX，Excel 第二阶段目前只深化 BH，尚缺完整的人工拆板回流工作台；CAM 工作包、Windows SinoCAM 自动排版、排版结果接纳和最终交付尚未形成完整生产能力；余料库尚未与 CAM 排版结果和自动选料形成闭环。平台当前仍使用 MySQL 消息传输，审计记录也不是密码学防篡改账本，后续还需补齐 RabbitMQ、TLS、外部只追加审计、集中监控告警以及 MySQL 与对象存储的联合备份恢复。

目前最重要的成果，是我们已经把生产资料从一批相互分散的文件，转化为能够沿明确流程流动的可信数据。自动化处理确定的部分，专业人员处理真正需要判断的异常，数据库保存组织记忆，权限系统保障协作边界，余料库继续沉淀材料资产。这套设计既取得了可量化的处理成绩，也为后续 CAM、SinoCAM、余料优选、生产计划和经营分析提供了可以直接复用的数据、任务、权限和工作流底座。
