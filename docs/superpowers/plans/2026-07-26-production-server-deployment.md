# 生产服务器部署实施计划

1. 为生产并发配置补充失败测试：API Worker、拆板、Excel、报告、MySQL 参数和
   `nofile` 必须可通过 `.env.docker` 配置。
2. 修改 Compose、容器启动命令和配置模板，使服务器容量参数可配置；保留安全默认值，
   不改变服务数量和发布器的 14 容器合同。
3. 运行基础设施、发布包、后端和前端回归门，构建新的 backend/frontend 保护镜像，
   验证镜像中没有业务 Python 源码。
4. 在服务器固化 `swappiness=10`，创建受限部署目录和一次性 GPG 密钥；使用服务器
   公钥生成不可变、加密的服务器专用发布包。
5. 传输并校验发布包，生成权限为 `0600` 的生产配置；使用新生成的数据库、对象存储
   和 JWT 密钥，保留本机同一组 `super_admin` 凭据。
6. 用全新命名卷启动 14 个容器，检查健康、重启次数、初始化日志、五金手册行数和
   存储桶。
7. 创建 `admin01`、`admin02`、`operator01`、`operator02`，四个账号密码使用用户
   指定值；验证唯一超级管理员保护规则和数据可见权限。
8. 用真实 DWG、DXF 和 Tekla Excel 执行上传、转换、分类、拆板、下载及多账号并发
   验收；检查文件原名、数量、进度、错误提示和产物可读性。
9. 清空验收产生的全部业务记录与 MinIO 对象，轮换最终 JWT，重建指定账号；确认最终
   数据库只含系统初始化数据、五金手册和五个账号。
10. 删除服务器部署私钥和发布中间文件，确认局域网入口、容器自启动、磁盘、交换空间、
    数据库连接、日志轮转及健康状态，提交并推送全部可提交改动。
