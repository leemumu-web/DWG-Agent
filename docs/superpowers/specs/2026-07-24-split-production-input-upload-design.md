# 生产输入分步上传设计

日期：2026-07-24

状态：交互方案已确认，待书面审阅

## 背景

当前生产工作流要求浏览器一次选择同一个文件夹，并在其中同时提交至少一个 DWG
和恰好一个 Excel。这与现场实际操作不符：Excel 数据表是独立文件，DWG 图纸是一组
文件，应当分步提交。

本设计以用户最新确认的规则为准，明确覆盖此前“所有上传统一为文件夹”的约束：
生产图纸仍以文件夹上传，Excel 是唯一允许单文件上传的生产输入。

## 目标

- Excel 与 DWG 分步上传，顺序不强制。
- Excel 只能作为单个文件上传，扩展名只能是 `.xls` 或 `.xlsx`。
- DWG 只能通过文件夹选择上传，至少包含一个 `.dwg`。
- DWG 文件夹混有其他文件时，必须由操作员确认后，只上传其中的 DWG。
- Excel 和 DWG 都通过服务器审核后，才能提交 DWG→DXF 转换并冻结输入版本。
- 继续复用现有 WorkflowInputBatch、WorkflowInputItem、Files、Jobs、对象存储和审计。

## 非目标

- 不允许人工上传 DXF；DXF 仍只能由服务器从已登记 DWG 生成。
- 不把 Excel 放进 DWG 文件夹上传。
- 不把 DWG 改成逐文件选择或单文件上传。
- 不改变冻结后的 DXF 主格式数据流、分类、Excel 处理或后续生产阶段。
- 不让服务器接收并存储操作员已确认忽略的文件。

## 上传合同

### Excel 单文件

工作流详情提供独立的“上传 Excel”入口，使用普通单文件选择器：

- 只允许选择一个文件；
- 文件扩展名必须为 `.xls` 或 `.xlsx`；
- 服务端继续执行 Excel 真实格式与 Stage 1 输入检查；
- 当前批次已有 Excel 时拒绝重复上传，操作员需先执行相应清理操作；
- 成功后登记为现有 `source_excel` 输入项。

前端的 `accept` 只用于改善选择体验，服务端扩展名和真实内容校验仍是权威边界。

### DWG 文件夹

工作流详情提供独立的“选择 DWG 文件夹”入口，继续使用浏览器目录选择能力：

- 选择结果必须来自同一个根文件夹；
- 至少包含一个 `.dwg`；
- 若文件夹只含 DWG，直接上传；
- 若同时包含其他文件，先展示确认窗口；
- 确认后只把 DWG 文件及其原始相对路径传给服务器；
- 取消确认时不上传任何文件，可重新选择文件夹；
- 当前批次已有 DWG 时拒绝重复导入，避免局部覆盖。

确认窗口显示：

- 将上传的 DWG 数量；
- 将忽略的文件数量；
- 将忽略文件的相对路径列表；
- 明确提示被忽略文件不会上传、入库或进入生产压缩包。

文件名匹配不区分扩展名大小写。人工 DXF、Excel、PDF、图片、临时文件和其他格式
均归入“忽略文件”，只有操作员确认后才继续；这些文件不发送到服务器。

## 后端接口

在现有工作流输入路由下拆分两个写入接口：

- `POST /api/v1/workflows/{workflow_id}/input-excel`
- `POST /api/v1/workflows/{workflow_id}/input-dwg-folder`

Excel 接口接收一个 multipart 文件；DWG 文件夹接口接收多个 multipart DWG 和与每个
上传项一一对应的 `relative_paths`。两者复用现有项目权限、输入批次锁、文件存储、
输入登记、失败补偿与审计能力。

旧的组合入口 `POST /api/v1/workflows/{workflow_id}/input-folder` 不再由前端调用，并从
公开路由移除，避免新旧合同并存造成歧义。

服务端 DWG 文件夹清单仍严格要求所有收到的文件均为 DWG。前端确认窗口不是安全边界；
绕过前端直接向 DWG 接口发送其他格式时，整个请求在对象入库前失败。

## 状态与清理

Excel 和 DWG 继续登记在同一个 WorkflowInputBatch 中，因此现有计数、转换、配对、
冻结和后续 artifact 逻辑不复制、不迁移。

界面分别展示：

- Excel：未上传或已校验的文件名；
- DWG：已登记图纸数量；
- DWG/DXF：服务器转换配对数量。

为保持整批输入一致性，冻结前继续复用“整批清空”操作；它会同时清除 Excel 与 DWG，
随后可重新分步上传。本次不增加逐文件替换能力。

## 数据流

1. 操作员创建生产项目并进入唯一工作流。
2. 操作员上传单个 `.xls` 或 `.xlsx`。
3. 操作员选择 DWG 文件夹；如有其他文件，确认仅上传 DWG。
4. 服务端分别审核并登记 Excel 与所有 DWG。
5. 两类输入齐全后，操作员提交 DWG→DXF 转换。
6. 服务端核对每个 DWG/DXF 配对和 Excel，冻结输入版本。
7. 后续阶段只流通服务器生成的 DXF；源 DWG 与 Excel 保留为输入档案。

步骤 2 和步骤 3 可以交换，但步骤 5 必须等待两者都完成。

## 错误处理

- Excel 扩展名不是 `.xls`/`.xlsx`：选择阶段提示并拒绝上传，服务端同样返回稳定错误。
- Excel 多选：浏览器入口本身禁止多选；服务端接口只接收一个文件。
- DWG 文件夹不含 DWG：提示重新选择，不显示“继续上传”操作。
- DWG 文件夹包含其他文件：只有确认后才上传筛选出的 DWG。
- DWG 文件夹来自多个根或相对路径不规范：服务端整批拒绝。
- 当前批次已有同类输入：返回 409，不追加或覆盖。
- 任一对象保存、内容审核或输入登记失败：该次请求整体回滚，不留下部分输入。

## 前端交互

生产输入面板保留当前工业工作台视觉语言，将上传区改成两个明确入口：

- “上传 Excel 文件”，附 `.xls / .xlsx` 和单文件提示；
- “选择 DWG 文件夹”，附“混入其他文件时确认后仅上传 DWG”提示。

两个入口在各自上传期间禁用重复提交。批次已有对应类型后，该入口禁用；整批清空后
恢复。转换按钮继续依据服务端批次计数启用，不依赖浏览器本地状态。

确认窗口使用现有 Ant Design `Modal`，不新增视觉体系。文件列表使用可滚动区域，
避免大文件夹撑高页面；按钮文案为“取消”和“确认，仅上传 DWG”。

## 测试与验收

后端：

- `.xls` 与 `.xlsx` 单文件分别可登记为 `source_excel`；
- 其他 Excel 扩展名、第二个 Excel 和伪造内容被拒绝；
- DWG 文件夹可登记一个或多个 DWG；
- DWG 接口收到非 DWG、多个根、危险路径或重复图纸名时整批拒绝；
- Excel 和 DWG 均存在后可转换并冻结；
- 只有其中一类输入时不能冻结；
- 任一步失败不留下部分 File 或 WorkflowInputItem。

前端：

- Excel 使用单文件选择器，`accept` 仅包含 `.xls,.xlsx`；
- DWG 使用文件夹选择器；
- 纯 DWG 文件夹直接上传；
- 混合文件夹展示忽略确认窗口；
- 取消不发请求；
- 确认请求只包含 DWG 及其原始相对路径；
- 无 DWG 的文件夹不允许继续；
- 两种输入齐全后继续现有转换与冻结流程。
