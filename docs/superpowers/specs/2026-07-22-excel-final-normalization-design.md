# Excel Final 规范化处理流程设计

**日期：** 2026-07-22
**范围：** `Stages/excel_final` 及其必要的 backend 持久化/API 接缝
**样本：** `Stages/excel_final/data/20260320-首都体育学院B7#地下部分-构件零件清单(毛净重)去gyb(3).xlsx`

## 1. 目标

在保留现有可靠 reader、pipeline、multi_split 和平台隔离执行边界的前提下，渐进式规范化 Excel Final 流程：

1. 从不成熟 ground truth 中无损分离真正的原始清单，建立可复现输入；
2. 统一 Tekla 与初始表入口的分类、拆板、五金手册、重量计算和输出规则；
3. 让理论单重、理论总重与源单毛重、表毛重形成有物理意义且可解释的核验关系；
4. 确保构件、零件、拆板子件、part 汇总和平台数据库之间身份可追溯；
5. 生成结构化处理报告，让“查无”、重量异常、隔离行和轮廓不确定不再只存在于日志；
6. 用真实样本关键事实和属性约束做回归，不逐单元格复制 ground truth 的旧错误。

本设计不做一次性全量重写。实现过程中保持仓库可测试、可回退，并复用现有 259 项 multi_split 回归测试。

## 2. 真实样本审查结论

源工作簿包含五个 sheet：原始 Tekla 清单、透视表、`整理`、`整理 (2)` 和 `part`。后四个 sheet 是人工或旧流程产物，只作为对照证据，不作为输入。

原始清单的已核实事实：

- 原始 sheet 为 584 行、17 列，真正题头位于第 6 行；
- 规范化后有 485 条真实零件行；
- 规格分布为 394 条 PL、42 条 BOX、41 条 TT、4 条 D 系列、4 条 NUT；
- 42 条 BOX 拆成 84 条子板行，最终整理表应有 527 条零件行；
- 普通 PL 中有 196 条能以严格物理条件证明为纯矩形；
- `PL10*135*250` 的理论矩形重为 2.649 kg，对应源单毛重 2.649 kg，而源单净重为 2.613 kg，说明理论矩形重应核验毛重；
- `PL16*628*628` 的理论矩形重为 49.535 kg，对应源单毛重 49.535 kg、源单净重 42.004 kg，进一步证明孔洞和切角主要体现在净重；
- `BOX700*700*36*36, L=3640` 的两块腹板理论合计为 1292.002 kg，两块翼板理论合计为 1440.130 kg，组合为 2732.132 kg，等于源整根 BOX 的单净/毛重；
- `D24, L=1000` 和 `D30, L=1000` 的源单重分别约为 3.551 kg、5.549 kg，符合实心圆钢规格；
- ground truth 将 BOX 标为 `BOX腹/BOX盖`，规范结果改为 `BOX腹/BOX翼`；
- ground truth 的普通 PL 在 part 中丢失构件编号，规范结果必须保留构件—零件对应；
- ground truth 的 `整理 (2)` 把 BOX 临时改写为 BH，此行为禁止进入规范结果。

ground truth 的测试角色是“规则化关键样本”：提取代表性行和整表约束，不把后四个 sheet 作为完整 golden workbook。

## 3. 总体架构

```text
不成熟 ground truth
  -> 预处理器：无损提取首个原始清单 sheet
  -> data/preprocessed/*_原表.xlsx（唯一 sheet：原表）
  -> 严格输入校验
  -> 无损原表 + 规范化父零件记录
  -> 分类 / 手册 / 父零件重量证据
  -> 拆板子行
  -> part 聚合 + 质量报告
  -> 六表最终工作簿 + backend/MySQL/API 结构化摘要
```

模块边界：

- `reader.py` 负责输入、题头、重复表头和行结构解析，不做重量计算；
- 统一领域记录保存源行、源序号、原数量、构件数、原规格和源重量；
- `spec_parser.py` 负责分类，`multi_split` 只接收已经确认可拆的类别；
- `handbook.py` 只做类型限定的只读查询并返回数值、来源和命中状态；
- 父零件重量证据在拆板前建立；拆板子行不重新解释父重量；
- 计算、核验、part 聚合和 writer 各自独立；
- 两个现有输入入口共用分类、手册、重量和核验逻辑；
- backend 仍通过隔离子进程运行 Stage，不把 Stage 变成长驻 backend package。

## 4. 输入与预处理契约

### 4.1 预处理产物

生成：

```text
Stages/excel_final/data/preprocessed/<原文件名>_原表.xlsx
```

要求：

- 只有一个名为 `原表` 的 sheet；
- 完整保留源首个清单 sheet 的题头、单元格值和类型、公式、样式、列宽、行高及工作表维度；
- 不复制透视表、旧整理表和旧 part；
- 不修改原 ground truth 文件；
- 写出后逐项验证源/目标单元格值与类型、样式 ID、行列尺寸和维度。

### 4.2 生产输入

- `.xlsx/.xlsm` 生产输入必须是预先分离的单 sheet 工作簿；
- 多 sheet 输入直接拒绝，不自动猜哪个 sheet 才是原表；
- Tekla 文本 `.xls` 仍保持单一文本源入口；
- 题头必须唯一可靠命中，不再回退“默认第 6 行”；
- 题头失败时报告前 15 行候选得分和缺少的必需字段；
- 原表在输出中无损保留；处理工作副本继续按已确认规则删除所有半角和全角空格。

### 4.3 重复表头

源表同时存在零件 `长度(mm)` 与构件形状 `长度(mm)`。工作副本必须按分组题头和数据语义规范为：

- 零件长度；
- 构件长度；
- 构件宽度；
- 构件高度。

最终整理表只保留一个规范的 `长度(mm)`，表示零件长度，以兼容 backend 表头读取。

### 4.4 清洗表和构件表

- `清洗表` 只含规范化零件行；
- 构件编号、构件数、批次等信息前向填充到每条零件；
- 构件首行、小计和总合计不留在清洗表；
- `构件表` 一构件一行，合并构件首行与小计数据，保留来源首行/小计行号；
- 重复构件编号只有在规格、数量和小计一致时才能合并；不一致时严重警告并隔离相关 part 行。

## 6. 分类与五金手册完整规则

本阶段将“五金手册数据库可用”作为前置条件，不设计数据库不可用降级分支。

| 优先级 | 输入类别 | 判定与输出 | 比重/理论重量 |
|---:|---|---|---|
| 1 | `PL6*30`，或中间状态“规格=6、宽度=30” | `类型=扁钢`、`规格=6*30`、`宽度=空` | 查询扁钢/扁铁表 |
| 2 | 其他显式 `PLt*w` | `类型=板材`；保持书写顺序，`规格=t`、`宽度=w` | 比重=7.85，按板材公式计算 |
| 3 | 明确 `FB/FLAT/扁钢/扁铁` | `类型=扁钢`；规格规范为 `t*w`，宽度空 | 查询扁钢/扁铁表 |
| 4 | 裸 `t*w` | 先查询扁钢/扁铁表 | 命中则为扁钢，规格 `t*w`、宽度空 |
| 5 | 裸 `t*w` 且扁钢表明确未命中 | 回退为板材，`规格=t`、`宽度=w` | 比重=7.85，按板材公式计算 |
| 6 | `BH H*B*tw*tf` | 自动拆为 BH腹/BH翼 | 按板材密度计算组合理论重量 |
| 7 | `BOX H*B*tw*tf` | 自动拆为 BOX腹/BOX翼 | 按板材密度计算组合理论重量 |
| 8 | `BT H*B*tw*tf` | 自动拆为 BT腹/BT翼 | 按板材密度计算组合理论重量 |
| 9 | 普通 `I` | 成品工字钢，不拆 | 查询工字钢表 |
| 10 | `D+直径` 且材质为 HPB…或 Q355B | 圆钢 | 查询圆钢表 |
| 11 | `D+直径` 且材质为 HRB… | 螺纹钢 | 查询螺纹钢表 |
| 12 | `D+直径` 且材质为其他值或空 | 分类不明 | 比重红色“查无”，来源注明材质不足 |
| 13 | 螺栓、螺母/NUT、螺套、TT | 保留对应类型和规格 | 比重、理单重、理总重留空；不查库、不标查无 |
| 14 | HN/HW/HM、槽钢、角钢、方管等明确型材 | 按前缀确定唯一类别 | 查询对应手册表 |
| 15 | 其他无法分类规格 | 未分类，保留原值 | 比重红色“查无”，报告源行 |

HA 不在本阶段业务支持范围内：不按 BH 拆板、不转换为 H 查询；出现时按无法分类规格处理。

手册查询要求：

- 查询前先确定唯一材料类别；
- 不在多个表之间按固定优先级取第一条；
- 裸 `t*w` 是唯一“先查扁钢、未命中再回退板材”的分支；
- 缓存键包含类别和规范化规格，D 系列还包含材质分类；
- 不使用猜壁厚、猜管材、猜类别的经验估算；
- 对应表在线未命中时，比重红色写“查无”；
- `比重来源` 记录板材常量、实际命中表、主动跳过或未命中；
- 平台继续通过环境变量传入只读连接；
- Stage 内删除明文默认数据库账户和口令。

真实数据库已只读验证：

- 扁钢表存在 `6*30 -> 1.413 kg/m`；
- 通用表的 `24`、`30` 同时存在圆钢和方钢，证明类别限定不可省略；
- 圆钢表存在 24 -> 3.55 kg/m、30 -> 5.55 kg/m；
- 螺纹钢表没有 24、30，不允许在 D 系列材质规则之外跨表兜底。

## 7. 拆板规则

### 7.1 几何和数量

- BH：腹板 `tw x (H - 2tf)`，数量 N；翼板 `tf x B`，数量 2N；
- BOX：翼板通宽、腹板内嵌；腹板 `tw x (H - 2tf)`，数量 2N；翼板 `tf x B`，数量 2N；
- BT：腹板 `tw x (H - tf)`，数量 N；翼板 `tf x B`，数量 N；
- 普通 I 不拆。

所有尺寸必须为正，且内嵌尺寸必须大于 0；否则严重警告并隔离出 part。

### 7.2 字段

- `截面型材` 永久保留源规格；
- BOX 不改写为 BH；
- `规格/宽度` 描述最终子板；
- 导入零件号为 `原零件号-类型`；
- 腹板是主行；
- 父单/总净重、单/总毛重、表净/毛重、表面积和组合理论重量只显示在腹板；
- 翼板重量、面积、比重、理单重、理总重显示为空；
- 系统内部仍计算翼板理论贡献；
- `原数量` 保留拆板前零件数量；
- `数量` 表示拆板后每个构件内实际板数；
- `总数 = 数量 x 构件数`；
- `理总重 = 父组合理论单重 x 原数量 x 构件数`。

## 8. 重量计算与物理核验

### 8.1 理论单重

- 普通 PL：`厚 x 宽 x 零件长度 x 7.85 / 1,000,000`；
- 扁钢和成品型材：`手册线重(kg/m) x 零件长度 / 1000`；
- BH/BOX/BT：每个父零件的一块完整截面所需全部腹/翼板理论重量之和；
- 紧固件、螺母、螺套、TT：留空。

### 8.2 精度

- 内部使用未舍入值完成乘法和核验；
- 单重、总重和表重落表统一保留 3 位；
- 不用显示后的单重反推总重；
- 表面积按源精度独立从未舍入几何值计算。

### 8.3 源重量链

```text
单净重 x 原数量 ~= 总净重
单毛重 x 原数量 ~= 总毛重
总净重 x 构件数 = 表净重
总毛重 x 构件数 = 表毛重
```

- 源字段乘法允许 0.1 kg 绝对误差；
- 单净重不得显著大于单毛重；
- 总净重不得显著大于总毛重；
- 违反物理关系时严重警告；
- 源重量缺失不回填理论值，不阻止尺寸完整的零件进入 part，但报告无法完整核验。

### 8.4 理论重与毛重

- 理单重主要核验源单毛重；
- 绝对误差 <= 0.01 kg 通过；
- 否则相对误差 <= 0.5% 通过；
- 0.5% 至 2% 为警告；
- > 2% 为严重异常；
- 几何理论重和手册理论重在报告中使用不同核验类别，避免标准版本差异被误写为几何错误。

### 8.5 净材利用率

```text
净材利用率 = 单净重 / 父理论单重
```

- 净重不要求接近理论毛坯重；
- 理论重作为毛坯上界；
- 净重超过理论值 0.5% 至 2% 为警告，>2% 为严重；
- 低利用率只记录，不设置任意下限；
- 样本合法 PL 的最低利用率约为 37.67%。

### 8.6 整表守恒

- 源净/毛重汇总只统计普通行和拆板主行；
- 翼板源重量为空，不参与源汇总；
- 整理表的表净/毛重汇总与构件表总计同时给出绝对差和相对差；
- 理总重按父零件口径汇总，不因拆板重复。

## 9. RECT 严格判定

### 9.1 普通 PL

只有同时满足以下条件时写 `文件=RECT`：

1. 单净重等于单毛重，且总净重等于总毛重；
2. 单毛重等于未舍入矩形理论重按 3 位舍入的结果；
3. 总毛重等于未舍入理论重乘原数量后按 3 位舍入的结果；
4. 单表面积等于矩形六面面积按 2 位舍入的结果；
5. 总表面积等于未舍入六面面积乘原数量后按 2 位舍入的结果；
6. 下料长度公式结果等于理论计算使用的长度；
7. 构件、零件、尺寸和材质无冲突。

样本中严格通过 196/394 条 PL。

### 9.2 自动拆板子件

自动拆板不无条件写 RECT。必须同时满足：

1. 父组合理论单/总重与源单/总毛重一致；
2. 父单/总净重与单/总毛重一致；
3. 拆板尺寸和数量合法；
4. 原长度没有进刀修正；
5. ID 无冲突。

无法证明 RECT 时 `文件` 留空，记录“轮廓未证明”，但不因此阻断 part。

扁钢不使用 RECT 推断。

## 10. 长度规则

- 左进、右进默认留空；
- 下料长度保留 Excel 公式，未填左右进时结果等于零件长度；
- Python 使用相同公式逻辑生成 part；
- 写出时公式单元格同时带已计算缓存值，使 backend `data_only=True` 能立即读取；
- 除下料长度外的派生字段保存计算数值。

- 致命：输入不是单 sheet、题头不唯一或缺必需列、工作簿损坏；不生成业务结果；
- 严重：关键字段缺失、ID 冲突、构件冲突、重量物理关系 >2%；保留在整理/报告，隔离出 part；
- 警告：手册查无、重量偏差 0.5% 至 2%、源重量缺失；生成结果；
- 信息：主动跳过手册、低利用率、RECT 未证明。

整单质量状态：

```text
ok
warning
severe_warning
```

严重和警告不把 Job 改成失败；结果仍生成，API 和工作簿明确返回质量状态及计数。

## 14. 错误与隔离

- 关键字段为零件号、规格、长度、材质、数量；
- 缺关键字段的零件保留在清洗表、整理表和报告，红色标记，不进入 part；
- 不用 `qty or 1` 等逻辑把空或零数量改成 1；
- 同构件同导入零件号的几何/材质冲突行不合并、不自动加后缀；
- 重复构件只有内容一致时才合并；
- 手册查无不修改源重量；
- 源重量缺失不以理论重量回填；
- 所有隔离决定记录明确原因和源行。
