# 生产工作流十阶段与视觉完善设计

## 目标

在现有 Linux 生产工作流上增加 Excel 第二阶段处理的正式位置，明确尚未上线的后续能力，
同时优化工作流前端的信息层级、视觉风格和易用性。页面继续表达真实系统状态，不用按钮、
进度或产物暗示未实现能力已经可用。

## 十阶段流程

`linux_production` 固定为以下顺序：

1. 文件接收与输入冻结；
2. DXF 分类与分流；
3. 图纸分类与拆板；
4. Excel 第一阶段处理；
5. Excel 第二阶段处理；
6. 深化设计完整性屏障；
7. CAM 工作包生成；
8. Windows CAM 排版；
9. CAM 结果接纳；
10. 交付与归档。

Excel 第二阶段使用稳定代码 `excel_stage2`，当前为 `placeholder`，执行种类为
`excel_stage2`。它读取 `stage1_excel` 和 `processed_dxf`，预留输出
`stage2_excel`。当前不注册执行器、不创建 Job、不产生模拟进度；流程到达该阶段后明确等待
能力上线或未来的真实产物交接。

深化设计完整性屏障、CAM 工作包和交付合同使用 `stage2_excel`，不再把
`stage1_excel` 当成最终生产 Excel。其余既有文件和阶段数据合同保持兼容。

## 能力状态与视觉层级

已实现阶段维持较强的工业控制台视觉：清晰编号、深青色当前态、低饱和绿色完成态和紧凑
业务说明。当前阶段应当是页面最明显的工作目标。

以下阶段统一标记“等待上线”并降低视觉权重：

- Excel 第二阶段处理；
- CAM 工作包生成；
- Windows CAM 排版；
- CAM 结果接纳；
- 交付与归档。

这些节点使用灰蓝色、虚线边界和低对比背景。选中后只显示一张紧凑说明卡，明确能力暂未
上线、数据接口已经预留、后续将在此接入；不显示执行、确认、阶段下载按钮或虚假进度。

图纸分类与拆板不是 CAM 阶段，保留“能力预留”区别，但删除重复的七项“未接入”指标，
改成简短边界说明和输入输出摘要。

## 生产产物与证据

全流程产物卡片改为按类型汇总：

- 显示“已登记 N 项”；
- 每种产物只显示一个 `类型 × 数量` 标签；
- 右侧保留“下载全部”；
- 删除逐产物版本、登记时间和纵向列表；
- 无产物时显示单行“暂无已登记产物”，不显示大尺寸空状态插图。

阶段专属下载、DXF 分类文件夹、任务记录和实际错误仍在其业务区域展示。汇总卡只负责提供
全流程概览和完整生产包下载。

## 易用性与响应式

- 阶段轨道中的编号、名称、状态和“等待上线”必须在桌面及窄屏下可读；
- 未来阶段仍可点击查看合同，但不能触发实际操作；
- 当前阶段、历史阶段和未来阶段有稳定且不只依赖颜色的文字标识；
- 卡片间距、标题和按钮尺寸统一，减少重复 Alert 与大面积空白；
- 产物类型较多时标签自动换行，不产生横向溢出；
- 下载失败继续使用结构化中文错误，不因视觉精简丢失请求信息。

## 错误与边界

- 后端对 `excel_stage2` execution 请求返回未实现能力错误；
- 未实现阶段不能通过执行 API创建 Job；
- 手工完成仍遵循既有真实交接产物校验，不能无产物绕过；
- 已实现阶段的下载、执行、重试和错误恢复行为不变；
- 旧 workflow 读取仍以其持久化阶段为准，新 workflow 使用十阶段模板。

## 验证

- 模板和架构测试锁定十阶段顺序、代码、模式及输入输出；
- HTTP/执行测试锁定 Excel 第二阶段不创建 Job；
- 前端合同测试锁定 `excel_stage2` 和“等待上线”文案；
- Playwright 验证阶段轨道、未来阶段无操作、图纸留白精简、产物类型计数、空状态和下载；
- 运行后端聚焦及全量测试、前端 production build、工作流及全量浏览器回归、文档和架构门禁；
- 最终检查运行服务、Git 工作树和远程主分支一致性。
