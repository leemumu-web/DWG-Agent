# 工作流操作提示与错误恢复设计

## 目标

让非程序员排版员在生产工作流第三阶段能够直接判断当前能做什么、失败影响什么、如何恢复，且所有服务端结构化错误保留错误码和请求编号，便于现场人员与管理员协同排查。

## 范围

- 统一工作流页面的 API 错误展示：错误事实、处理建议、请求编号和明确重试动作同屏显示。
- 完善“分类图纸导出”和“分批导出并清理”：无可导出文件时说明原因；原生下载启动后保留可重试入口；下载失败不误报文件已删除。
- 对暂不可用的导出入口说明禁用原因，例如拆板仍在执行、当前 run 未形成结果或没有当前批次。
- 保留现有工业化浅色界面、工作流阶段轨道、主仓库正式拆板下载与服务器清理合同。

不改变后端分类口径、拆板算法、ZIP 目录、文件删除语义或阶段自动推进规则；不重绘其他业务页面。

## 交互规则

1. 页面级读取失败使用常驻错误块，主标题说明失败对象，正文显示服务端原始业务说明，随后给出与 HTTP 状态对应的处理建议。
2. 401/403 引导登录或联系管理员；404 引导刷新或返回；409 引导刷新当前状态后再操作；413/415/422 引导调整输入；429 引导等待；5xx 和网络错误引导保存请求编号并重试一次。
3. 请求编号和错误码必须可见，但不得显示 traceback、本机路径、DSN 或任意响应对象。
4. 分类图纸导出创建成功后弹窗不立即关闭，显示文件数、总大小、文件名、有效期与“再次开始下载”；操作员可确认浏览器下载栏后主动关闭。
5. 两类导出预览没有任何可用类别时显示“当前没有可导出的文件”，而不是只留下不可点击按钮。
6. 禁用导出按钮使用悬浮提示说明原因；按钮名称使用“分类图纸导出”和“分批导出并清理”，避免含义相近。

## 组件边界

- `shared/components/ApiErrorAlert.tsx` 只负责把 `parseApiError` 结果转成安全、可恢复的常驻提示，不拥有业务请求。
- `shared/api/error.ts` 增加安全的状态字段和恢复建议函数，继续作为唯一错误 envelope 解析边界。
- 两个导出控件各自拥有预览、创建、状态和重试；组合组件只计算是否禁用及原因。
- `DrawingProcessingPanel.tsx` 使用共享错误提示读取 run，不复制错误解析规则。

## 验证

- Playwright 先覆盖：选择导出创建后可再次下载；预览失败展示错误码、请求编号、处理建议并可恢复；空预览有明确说明；运行中按钮说明禁用原因。
- 前端生产构建、工作流 E2E、全量浏览器回归必须通过。
- 后端前端合同测试锁定共享错误组件和新的操作文案，防止退回短暂且不可恢复的提示。
