# 前端弱网通信与真实懒加载设计

## 目标

在服务器可用但网络短暂抖动、后台状态持续变化和页面包含重型业务模块时，前端保持已有数据、提供明确操作状态并减少首屏无关代码。交互优化不得通过盲目重试写请求、隐藏冲突或降低数据校验来换取表面流畅。

## 已确认基线

- Axios 默认超时 30 秒，401 刷新已合并并只重放一次原请求。
- React Query 查询最多重试两次瞬时错误，mutation 默认不重试。
- 已有浏览器 offline banner，但恢复后主要依赖用户手工刷新。
- 路由已经使用 `React.lazy`，但从 feature 的聚合 `index.ts` 导入，同一 feature 下多个页面仍可能合并成一个业务块。
- 当前生产构建的最大公共 JS 块为 760.65 kB（gzip 253.32 kB），workflow JS 块为 119.67 kB（gzip 34.22 kB）；构建已产生大于 500 kB 警告。
- 全局 Suspense 包住整个 Routes，路由切换时可能让整个内容区域只剩一个通用 Spin。

## 通信策略

### 查询

- GET/HEAD 查询仅对无响应网络错误、408、429、502、503、504 重试，最多两次。
- 延迟使用全抖动指数退避并尊重 `Retry-After`；429 不进行密集立即重试。
- `refetchOnReconnect` 开启，恢复联网后只刷新当前可见、已过期的查询。
- 页面切换和分页使用上一份成功数据作为 placeholder，后台刷新不把表格清空。
- 查询函数接收 AbortSignal；路由离开、参数变化和新查询取代旧查询时取消无用请求，防止旧响应覆盖新状态。
- 对正在转换/运行的资源使用当前已有的有界轮询或 SSE；终态立即停止轮询。不能用 `networkidle` 判断业务就绪。

### 写命令

- 全局 mutation `retry` 保持关闭。
- 新增显式 `reliableCommand`，只允许规格列出的幂等 JSON 命令使用稳定键和有界重试。
- 大文件、multipart、下载生成和未知副作用不经过 `reliableCommand`。
- 相同 UI 操作的 stable key 在服务器确认前保留；成功、确定性业务失败或用户明确放弃后清除。
- 409 版本冲突不自动覆盖。前端展示服务器当前版本并刷新权威资源；可收敛的“已执行”响应按成功复用展示。
- 认证刷新仍保持单飞；刷新失败只清一次会话，不让并发请求触发重复跳转。

### 连接状态与反馈

- offline banner 增加恢复中与已恢复状态；恢复后显示正在同步，而不是立即宣称数据最新。
- 命令反馈采用持久的页面内状态：确认受理、等待投递、执行中、成功、失败/冲突。toast 只作辅助。
- 操作状态区域使用 `aria-live="polite"`；错误保留请求编号和已有结构化恢复建议。
- 断网期间不丢弃表单、文件清单、当前分页和已完成上传进度。

## 懒加载与分包

### 页面边界

- 路由动态导入直接指向页面模块，不经过 feature 聚合出口。`WorkflowsPage` 与 `WorkflowDetailPage`、identity 的登录/用户/角色/个人页、operations 的控制台/审计页分别形成页面边界。
- 认证外壳和 AppLayout 保持稳定；每个路由内容区拥有自己的 Suspense fallback，切换页面不卸载全局导航、断网提示和错误边界。
- 404/重定向和权限守卫保持轻量，不预加载无权限页面。

### 工作流详情内部

- 首屏只同步加载工作流概要、阶段轨道和当前阶段最小交互。
- Excel、分类、拆板、归档和大型预览面板在对应阶段被选择或即将进入时再加载。
- 当前阶段数据就绪后，使用 `requestIdleCallback`（带超时和兼容 fallback）预取下一个高概率页面/阶段模块；省流或慢连接提示下不主动预取大块。
- 懒加载失败提供局部重试按钮；一次 chunk 网络失败不能触发整页错误或丢失当前查询缓存。

### 构建预算

- 构建输出生成 manifest，由测试计算入口与路由依赖，不只搜索 `lazy(` 字符串。
- 不允许任何业务路由把另一个无关重型页面作为静态依赖。
- 最大单个 JS 块必须消除当前大于 500 kB 的构建警告，或由明确、可缓存且不进入全部首屏的 vendor 分组替代；不能只调高 warning limit。
- 登录页、生产项目列表和工作流详情的初始 gzip 依赖分别与本设计基线对比，任何增长必须有说明；列表页不得预取详情全部阶段。
- workflow 列表与详情必须形成不同入口块；阶段重型面板必须在构建 manifest 中保持动态依赖。

## 组件与数据体验

- 列表刷新保留行、筛选和滚动位置，显示非阻塞刷新指示。
- mutation 成功后优先把服务器响应写入精确 query cache，再按需 invalidate；避免先清空再全量加载。
- 使用资源版本或 request generation 防止过时响应回写。
- 同一资源的互斥动作共享 pending 状态；例如转换提交期间禁止冻结和清空，但允许查看、离开和刷新。
- 大型列表继续服务端分页；不因“流畅”重新全量抓取并在浏览器拼接。
- 骨架尺寸尽量接近最终内容，减少布局跳动；不增加动画负担。

## 错误处理

- 复用 `parseApiError` 的结构化分类，补充 outbox pending、命令回执、版本冲突和上传会话错误码。
- chunk 加载失败、API 网络失败、认证失败和业务冲突使用不同文案与恢复动作。
- 未收到响应的写请求文案必须说明“服务器可能已经受理，正在确认”，不能直接提示重新提交。
- 只有服务器返回权威未受理状态后，才重新启用会产生新意图的按钮。

## 测试门槛

### 单元/契约

- 查询重试状态白名单、次数、抖动上限和 `Retry-After`。
- mutation 全局不重试；multipart 不进入可靠命令；稳定键在不确定结果时保留。
- AbortSignal 和请求 generation 防止旧响应覆盖。
- 路由直接模块导入、局部 Suspense、阶段动态依赖和构建 manifest 预算。
- 离线/恢复状态机、query cache 保留和可访问提示。

### Playwright

- GET 先 503 后成功，页面保留已有数据并恢复。
- POST 在服务端提交后中断响应，前端用相同键确认并只显示一个结果。
- 转换按钮快速双击和多标签页操作不产生重复逻辑任务。
- 离线期间保留表单与上传进度，恢复后先同步再继续。
- 路由 chunk 首次加载失败可局部重试，导航和已加载页面不消失。
- 使用可见业务控制判断就绪，不使用 `networkidle`。

### 构建与真实服务

- `tsc`、架构检查、Vite 生产构建和 manifest 预算通过。
- 在实际 Nginx 压缩和缓存头下验证首屏、二次访问和按需 chunk。
- 使用受控网络限速/延迟/断线进行真实浏览器验证，不把 mocked route 作为唯一证据。

## 发布与回滚

- 新旧前端都兼容已有 API；可靠命令和上传会话先由后端上线并通过健康门禁，再切换前端入口。
- 静态资源使用内容哈希和长期缓存，`index.html` 不长期缓存；旧页面打开期间仍能下载旧 chunk，发布清理不得立即删除仍被旧 HTML 引用的资源。
- 前端可单独回滚到旧镜像；后端新增幂等/outbox 数据保持有效，不因前端回滚删除。

## 非目标

- 不重做整体视觉语言或导航信息架构。
- 不用 Service Worker 缓存业务 API 或保存敏感响应。
- 不对所有页面做无条件预取。
- 不通过更长超时、更多并发或更多自动重试掩盖后端状态不明确。
