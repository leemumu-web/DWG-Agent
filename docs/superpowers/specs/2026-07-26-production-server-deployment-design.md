# 生产服务器部署设计

## 目标与边界

将已验证的无业务源码镜像部署到 `192.168.188.50`，对服务器所在
`192.168.188.0/24` 局域网提供浏览器入口。服务器最终只保留运行所需镜像、
配置和数据卷，不保留仓库源码、镜像明文归档或部署私钥。

部署完成后：

- 业务数据库没有验收任务、文件、工作流或转换记录；
- 保留系统角色、权限、唯一 `super_admin`、两个 `admin` 和两个 `operator`；
- 五金手册由随版本发布的 SQL 初始化，是 Excel 查询的唯一标准；
- MySQL、MinIO 不映射宿主机端口，只有 Nginx 的 HTTP 入口和服务器 SSH 可达；
- DWG 仅用于第一阶段输入，后续阶段继续使用服务器生成并登记的 DXF。

## 服务器容量

实机为 Ubuntu 22.04、16 vCPU、62 GiB 内存、2 TiB 虚拟磁盘。
根逻辑卷在线扩展到 1,800 GiB，卷组保留 246 GiB 空闲空间，供快照和应急扩展。
现有 8 GiB 交换空间保留；在当前内存规模下不额外扩容，将
`vm.swappiness` 调整为 10，只有实测持续出现内存压力才扩大交换空间。

虚拟机向来宾暴露的是 Core2 级指令集，不满足 x86-64-v2。基础设施镜像因此锁定为
实际在目标机验证过的 MySQL 8.0.45 Debian 摘要和 MinIO 2024-12-18 摘要。
MinIO 服务直接启动官方静态二进制，并用静态 `mc ready` 探测，避免执行 UBI9
中要求 x86-64-v2 的 glibc 入口脚本。镜像仍由发布器重标记并离线封入加密包。
业务镜像的 NumPy 固定在 2.3 系列，其官方 wheel 基线为 SSE/SSE2/SSE3；
发布器会读取 wheel 的 SIMD 基线并拒绝任何要求 x86-64-v2 的构建。

Docker 数据继续位于根文件系统。应用、MySQL 和 MinIO 使用命名卷，日志启用大小
和份数限制，避免长期运行把磁盘写满。

## 并发预算

并发按任务物理成本分配，而不是把所有队列同时拉满：

| 处理单元 | 生产并发 | 依据 |
| --- | ---: | --- |
| API | 8 | 覆盖多账号上传、查询和下载，主要是 I/O |
| DWG→DXF | 4 | ODA 为重 CPU/内存进程 |
| DXF→DWG | 2 | 独立工具，避免与主流程争抢全部 CPU |
| DXF 分类 | 1–4 自动伸缩 | 单图隔离且可按积压扩容 |
| DXF 拆板 | 2 | 每任务独立临时目录和任务账本 |
| Excel Final | 2 | 每任务独立临时目录和结果账本 |
| 报告 | 2 | 轻量 I/O/排版任务 |
| 余料转换/解析 | 2/4 | 沿用已验证边界 |
| 维护 | 1 | 保证清理操作串行 |

Celery 每个任务仍按当前 attempt 领取，拆板和 Excel 的输入、输出临时目录包含任务
标识，不共享工作目录。提高并发只允许不同任务并行，不允许同一任务重复运行。

MySQL 初始使用 16 GiB InnoDB 缓冲池、300 个最大连接、合理的表和线程缓存。
API/Worker 连接池保持小池，避免进程数乘以大连接池耗尽 MySQL。
所有长驻容器的 `nofile` 软硬限制设为 65,536。

## 安全与发布

服务器生成一次性 GPG 部署密钥，私钥不离开服务器。本机构建端只导入其公钥，
将已验证镜像重新封装为服务器专用加密包。安装完成并验证镜像后删除：

- 服务器一次性私钥；
- 上传的加密包；
- 解密后的镜像归档；
- 构建端临时公钥目录。

运行配置权限为 `0600`。远端生成新的 JWT、MySQL 和 MinIO 密钥，只复用本机已验证
的 `super_admin` 用户名和密码。镜像内只保留编译字节码；这能阻止直接查看业务源码，
但不宣称能抵御拥有服务器 root 权限的专业逆向。

内网使用同源 HTTP，刷新 Cookie 明确配置为允许内网 HTTP。若以后开放公网，必须先
加 TLS 并恢复 Secure Cookie。

## 数据与验收

首次启动使用全新 Docker 数据卷。真实验收按以下顺序进行：

1. 检查 14 个容器健康、无重启、MySQL/MinIO 连通；
2. 使用唯一 `super_admin` 创建两个 `admin` 和两个 `operator`；
3. 分别登录五个账号，确认管理员可见全局、操作员仅见本人数据；
4. 实际上传 DWG，完成 DWG→DXF、分类、拆板、下载；
5. 实际上传 Tekla Excel，完成 Excel Final 并下载单个结果工作簿；
6. 多账号并发提交，核对输入数、成功数、输出数、原名和进度；
7. 观察 CPU、内存、MySQL 连接、队列、容器重启和错误日志；
8. 清除所有验收业务数据和对象，轮换最终 JWT 密钥，重建五个账号；
9. 再次确认数据库没有任务/文件/工作流记录，五金手册与账号仍正常。

最终访问地址为 `http://192.168.188.50/`。MySQL 与 MinIO 仅在 Compose 内部网络
可用，不直接暴露给局域网。
