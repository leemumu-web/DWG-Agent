# DXF 分类分流多项目自动伸缩设计

## 目标

让不同生产项目的 DXF 分类任务能够并行执行。分类队列空闲时只保留一个执行进程；多个项目排队时自动扩展，最多同时执行三个项目。

本次不拆分单个项目内部的 DXF 文件，也不改变分类规则、数据库结构、前端展示和拆板输入合同。

## 运行模型

`dxf_classification` 继续使用独立 Celery 队列和单个受管 worker 节点。该节点由 Celery prefork autoscaler 管理执行进程：

- 最小进程数：`1`
- 最大进程数：`3`
- 任务预取：`1`
- 一个分类 Job 占用一个执行进程

有一个项目时保持一个进程；第二、第三个项目进入队列后按需扩容；任务结束并空闲后由 Celery 自动收缩。第四个及后续项目留在队列中等待，不会被同一个进程提前预取。

## 配置与启动

增加两个环境配置：

- `DXF_CLASSIFICATION_AUTOSCALE_MIN=1`
- `DXF_CLASSIFICATION_AUTOSCALE_MAX=3`

启动脚本校验两者均为正整数且 `MIN <= MAX`。本机默认采用 `1–3`，配置示例和配置参考同步说明用途。

`scripts/lib/cad_worker.sh` 仍是本地 worker 拓扑的唯一来源。分类 worker 使用 `--autoscale=3,1` 启动，不同时传入固定 `--concurrency`。其他 worker 保持现状。

`start-all.sh` 继续先停止旧运行、同步环境，再按当前配置启动全部服务。`status.sh` 对分类 worker 显示自动伸缩范围，并验证实际进程命令包含期望的 autoscale 参数，避免旧配置进程被误报为正常。

## 数据与事务边界

每个分类任务继续使用独立的：

- workflow ID、stage run 和 Job attempt；
- 临时输入输出目录；
- MinIO 对象键前缀；
- 分类 run、item、报告和清单；
- `workflow_artifacts` 当前工作流阶段锁。

不同项目不会争用同一阶段锁。相同 Job 的重复投递仍由 Job claim 拒绝重复执行；同一工作流的产物替换仍保持整批写入和 MySQL 1020 单次重试。

## 资源与失败处理

最大并发限制为三个分类任务，避免无界扩容。分类子进程超时、任务失败和人工重试继续沿用现有 Job 状态与审计事件。

单个子进程异常退出时，其他项目的执行进程不受影响。Celery 的 late acknowledgement、现有任务恢复与 stale Job 对账机制继续负责异常恢复，不引入新的任务状态。

## 验证

实施采用测试先行：

1. 启动脚本测试先证明当前分类 worker 尚未支持 autoscale。
2. 覆盖默认 `1–3`、环境变量覆盖、非法范围拒绝和其他 worker 不受影响。
3. 保持分类持久化、跨阶段衔接和 MySQL 1020 回归测试通过。
4. 完整执行 `start-all.sh`，确认旧 worker 已退出。
5. 验证分类 worker 命令行包含 `--autoscale=3,1`、空闲时保留一个子进程、状态脚本全绿。

## 完成标准

- 多个项目的分类任务最多可同时运行三个；
- 无任务时分类 worker 自动收缩到一个执行进程；
- 同项目幂等、跨项目数据隔离和分类产物合同不变；
- 启动、停止、状态检查、配置文档和自动化测试保持一致；
- 代码提交并推送到远程 `main`。
