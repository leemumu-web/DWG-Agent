# Excel Final 同类表适配与鲁棒性设计

## 目标

把 Excel Final 从“能稳定处理当前 B7 样表”深化为“能可靠处理同类 Tekla 构件零件清单和初始表”的 Stage，同时保持已确认的手册、重量、拆板、part 和最终 Excel 合同。

最低真实验收输入为：

`Stages/excel_final/data/003郑州宝冶-构件零件清单(毛净重)去构造板.xlsx`

历史语料使用 `Data/十份排版` 中去重后的“构件零件清单毛净重”文件。只有构件汇总、没有零件明细的“构件清单新”不属于可处理输入，必须明确拒绝，不得伪造零件或 part。

## 已验证事实

- B7 输入：485 个父零件、46 个构件，当前规范结果满足 22 条对账规则。
- 003 输入：表头在第 6 行，共 6892 个父零件、688 个构件；当前 Reader 可以完整读取，无 Reader 问题。
- 003 当前基线：7399 行整理表、2959 行 part；最终整理表 48619 个公式、part 2959 个公式。
- 003 当前报告有 635 行，其中 573 行为五金手册查无；D8/Q235B 和 D12/Q235B 分别重复 306 与 75 行。
- 11 份历史“毛净重”表含 6713 个零件。当前严格合同因把“批次”设为必填而全部拒绝。
- 历史空格文本是固定宽度格式。现有按空白分隔再补列的实现会丢失空字段并使螺栓行错列。
- 格式识别与初始表签名分别在 Stage CLI 和后端重复实现。
- BH/BOX/BT 规格解析在理论重、拆板和公式写出中重复使用不同正则；旧模块支持 BOX 三参数简写，规范主链不支持。

## 不改变的业务规则

- 板材比重固定为 7.85。
- 扁钢先查五金手册，查无时按已确认规则回退裸厚宽板材。
- 螺栓、螺套和 TT 不查手册，比重与理论重留空。
- 其他手册查无使用红色提示并进入精炼报告。
- D 系列按材质路由：HPB/Q355B 查圆钢，HRB 查螺纹钢；Q235B 未经确认，继续查无，不擅自扩展。
- 表单重、理论单重及单重/总重/构件数的物理关系继续核验。
- BH/BOX/BT 子板保留导入构件号；普通板材和扁钢按完整参数跨构件合并。
- 最终整理表删除类型、比重来源、净材利用率和重量核验；最终 part 删除类型。内部导入副本保留完整字段和功能。
- 最终可见计算字段保留公式与缓存，part 汇总引用明确的整理表贡献行。

## 架构

### 1. 深化 Excel Final 输入接入 Module

建立一个外部 Interface：

`read_production_source(path) -> SourceIntakeResult`

调用者只需知道输入路径、输入级错误模式和统一结果，不再知道固定行号、编码、分隔方式或表头评分细节。

`SourceIntakeResult` 包含：

- `source_path`
- `source_format`
- `sheet_name`
- `working_values`
- `parts`
- `component_rows`
- `issues`
- `diagnostics`

内部有四个真实 Adapter：

1. 标准 Tekla 工作簿 Adapter
2. 初始表工作簿 Adapter
3. 制表符 Tekla 文本 Adapter
4. 固定宽度 Tekla 文本 Adapter

Stage CLI、Stage runner 和后端不再分别猜格式。后端完成文件落地后把路径交给 Stage；Stage 在同一 Interface 内检测和读取。

### 2. 表头 Schema 与字段要求

表头 Schema 集中维护规范字段、别名、必填级别和冲突规则。

规范别名至少覆盖：

- 构件编号 / 构件号
- 零件号 / 零件编号
- 规格 / 型材 / 截面型材
- 单表面积 / 单面积 / 单涂装面积
- 总表面积 / 总面积 / 总涂装面积
- 单重 / 单毛重
- 总重 / 总毛重

核心必填字段为构件身份、零件身份、规格、零件长度、材质和数量。批次是可选上下文，不得阻止没有批次列的合法 Tekla 清单。

同一行出现两个同分且完整的表头候选，或一个源列同时映射到多个核心字段时，整份拒绝并输出候选行、得分、缺失字段和冲突别名。

### 3. 行角色判定

在列位已经可靠恢复后，用字段存在性和明确小计标记判定：

- 构件起始行：构件号存在、零件号为空
- 零件行：零件号存在
- 构件小计行：明确的小计词且能关联构件
- 空行/页眉/页脚：无业务载荷

不得再用零件号命名正则决定行类型。命名模式只能作为诊断信息，不能改变列位。

输入级结构已唯一识别后，单行缺字段、非法数值或物理冲突继续生成 `QualityIssue`，保留在清洗表/整理表并隔离出 part。

### 4. 固定宽度文本 Adapter

无制表符的 Tekla 文本按表头字符位置建立列跨度，逐行按跨度切片，保留中间空字段。若表头跨度不能唯一恢复，整份拒绝。

不得使用 `\s+` 压缩空白后再按列号解释业务值。`pandas.read_fwf` 可用于候选跨度辅助，但最终 Schema 映射必须验证核心字段和样本行的数值形状。

### 5. 深化组合截面几何 Module

建立一个内部 Interface：

`parse_fabricated_profile(spec) -> FabricatedProfile`

`FabricatedProfile` 统一表达类别、高、宽、腹板厚、翼板厚和拆板倍数。理论重、拆板、质量诊断和 Excel 公式生成只消费此结果，不再各自解析字符串。

支持：

- BH/BOX/BT 四参数
- BOX 三参数简写，第三参数同时作为腹板厚和翼板厚

非正尺寸、简写类别不允许或无法唯一解释时生成拆板几何异常，不猜测。

### 6. 精炼处理报告

逐行 `QualityIssue` 保留，用于样式、隔离、影响范围统计和后端关系数据。最终处理报告按可操作问题签名聚合：

- 级别
- 类别
- 规格或冲突对象
- 涉及字段
- 建议操作

说明包含影响行数和最多三个代表来源。严重问题与警告分别聚合，不跨级别。

例如 003 的 D8/Q235B 306 行和 D12/Q235B 75 行应收敛为两个查无项，而不是 381 行。报告仍只列明确需要人工操作的核心问题；无问题时 `A2=无`。

`PipelineOutcome` 不扩张现有版本化协议：质量状态由聚合后的人工处置项决定，`warning_count`、`severe_warning_count` 和 `report_summary.category_counts` 继续表示最终处理报告的合并行数，并与后端从工作簿回读的口径一致。每个聚合项在“说明”中明确受影响原始行数；逐行问题仍保留在流水线内部，用于单元格样式、part 隔离、影响范围统计和代表来源选取。

### 7. 大表性能

所有验证必须与单元格数和公式数近似线性：

- 禁止在 openpyxl `read_only=True` 工作簿上对数千坐标随机访问。
- 公式和缓存验证一次加载、一次扫描或内存索引。
- 手册查询继续按类别、规格、材质缓存。
- 003 端到端基线约 43 秒；实现后不得因新 Adapter 或验证出现平方级增长。

## 错误处理

- 文件扩展名、工作表数、格式、表头或列位歧义：输入级失败，返回可操作诊断。
- 只有构件汇总而无零件明细：输入级失败，说明该文件不是构件零件清单。
- 单行缺字段或非法数值：保留审计行、标红、报告并隔离出 part。
- 手册未命中：按既有策略警告或明确跳过，不中止整份。
- 拆板几何无法解释：保留父行、严重报告、不进入 part。
- 公式与缓存不一致：原子写出失败，不替换目标文件。

## 测试与验收

### 单元与接口测试

- 表头别名、可选批次、重复长度组、歧义候选。
- 初始表元数据和表头不固定在第 1/2 行。
- 制表符文本与固定宽度文本得到相同规范记录。
- 固定宽度螺栓空规格不发生列位左移。
- BH/BOX/BT 统一解析；BOX 三参数和四参数在理论重、拆板和公式中一致。
- 构件清单新明确拒绝。
- 报告按问题签名聚合，但逐行状态和隔离不变。

### 真实语料

- B7 结果继续满足 22 条对账规则。
- 003 完成真实 MySQL 处理，6892 父零件和 688 构件不丢失；最终删列和公式合同保持。
- 历史 11 份“毛净重”输入至少全部通过 Source Intake；每份父零件数、构件数和隔离原因形成可复查清单。
- “构件清单新”语料全部按明确原因拒绝。

### 后端链路

- 自动识别不再由后端重复实现。
- 上传、Job、内部导入、对象存储、下载全链路通过。
- 数据库保留类型、比重来源、利用率和重量核验。
- 下载工作簿不恢复已删除列，公式与缓存均存在。

## 实施顺序

1. 先建立语料探测测试和输入 Interface。
2. 合并表头 Schema 与格式识别。
3. 实现固定宽度 Adapter 和动态初始表 Adapter。
4. 统一组合截面几何解析。
5. 精炼报告且保持逐行质量统计。
6. 接入后端自动入口，删除重复识别代码。
7. 跑 B7、003、历史语料和后端真实流。

每一步必须保持可构建、可回滚；不得用当前样表的固定行数或公式数量作为生产逻辑。
