# API 4xx 闭环与运维脚本设计

## 背景与现场证据

2026-07-18 生产式本地入口 `http://127.0.0.1:8080` 出现文件夹操作失败。Nginx access log、FastAPI 日志、进程启动时间与 Git 提交时间共同确认：

- Windows 客户端在 11:15-11:16 连续三次调用 `POST /api/v1/files/batches/bulk-delete`，均返回 405。
- FastAPI 进程启动于 09:32，而批量文件夹删除路由在 09:58 才加入代码。现有 `scripts/start-all.sh` 只检查 8010 端口，端口已占用时不会检查运行进程是否早于后端代码，也不会重启旧进程。
- 同一客户端随后调用 `POST /api/v1/files/download-zip` 返回 409。前端弹窗默认同时选择 DWG 和 DXF，后端则要求每个文件的每个请求格式都存在；任一文件尚无转换结果时返回 `FILE_EXPORT_FORMAT_UNAVAILABLE`，且当前弹窗在失败后自动关闭。
- 当天其他非 499 的 4xx 包括刷新令牌 401、固定不存在 ID 的 404、无效请求体 422 和不可重试 Job 的 409。请求时段与测试输入表明多数来自鉴权或契约测试，不应被误判为生产缺陷。
- Nginx 499 表示客户端在响应前断开，不是 FastAPI 主动返回的 4xx。它在页面切换、请求取消、SSE 关闭和上传中均可能出现，必须单独统计，不能与应用 4xx 合并成同一故障结论。

## 目标

1. 消除运行服务落后于代码造成的新接口 405，并让脚本主动发现版本漂移。
2. 在 ZIP 提交前提供与真实打包一致的格式可用性判断，避免可预防的 409。
3. 保持 ZIP 的全量一致性：不静默跳过文件或格式，不生成看似成功的不完整包。
4. 建立一条生产运维闭环，统一诊断服务、依赖、代码漂移和近期 HTTP 异常。
5. 更新生成式 API 文档与脚本使用文档，并以自动测试覆盖错误恢复。

## 非目标

- 不把预期的 401、404 或 422 改成 200。
- 不掩盖合法的冲突响应，也不降低文件、Job、权限和存储一致性校验。
- 不把所有 499 视为服务故障；只识别异常集中或长耗时断开。
- 不重写现有启动、数据库、SSH 转发和 CAD worker 脚本。

## ZIP 打包预检

### API

新增 `POST /api/v1/files/download-zip/preview`，请求体与正式下载一致：

```json
{
  "file_ids": [101, 102],
  "formats": ["dwg", "dxf"],
  "folder_name": "图纸导出"
}
```

响应按格式返回完整覆盖情况，并给出有限的缺失样本：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "file_count": 2,
    "formats": [
      {"format": "dwg", "available_count": 2, "missing_file_ids": [], "complete": true},
      {"format": "dxf", "available_count": 1, "missing_file_ids": [102], "complete": false}
    ],
    "can_download": false
  },
  "request_id": "..."
}
```

预检与正式 ZIP 共用同一个解析函数，统一处理 ID 去重、源文件存在性、读取权限、源格式和生成结果映射。预检只检查元数据可用性，不读取全部对象字节；对象在预检后丢失时，正式下载仍返回 `STORAGE_INCONSISTENT` 409。

`missing_file_ids` 受固定样本上限约束，同时返回准确缺失数量，避免大请求产生超大错误体。源文件不存在或无权限继续使用现有 404/403 语义。

### 前端

- 弹窗打开或所选文件变化时自动预检 DWG/DXF 两种格式。
- 每个格式显示“可用 N / 共 M”；不能覆盖全部文件的格式禁用，不允许构造必然失败的正式请求。
- 默认选择当前页面的源格式；目标格式仅在完整可用时自动选择或允许勾选。
- 预检加载、失败和空选择都有明确状态；预检失败时不提交正式 ZIP。
- 正式下载收到 409、网络错误或其他失败后保留弹窗、选择和文件夹名，显示安全错误详情并允许重新预检和重试。
- 预检与正式请求之间存在状态竞争，因此后端严格校验仍是最终权威。

## 405 与运行代码漂移

### 即时恢复

完成代码和回归测试后，安全重启本地 FastAPI，使当前运行进程加载已经提交的批量删除路由。重启前后检查 `/health/ready`，并用只读的路由能力探测确认该路径不再返回 405；不得以真实文件夹删除作为探针。

### 持久修复

- `scripts/start-all.sh` 增加显式 `--restart-backend`，使用现有 PID/进程识别与端口等待能力执行受控重启。
- 普通启动发现后端代码或依赖锁文件的修改时间晚于本项目 FastAPI 进程启动时间时，输出明确漂移告警及修复命令，不擅自中断正在处理的请求。
- 前端 `dist/index.html` 早于 `src/`、依赖清单或构建配置时，普通启动判定构建产物过期并重建；不再只检查 `dist` 是否存在。
- `scripts/status.sh` 和新诊断脚本报告运行进程启动时间、代码最新修改时间及漂移状态。

## 4xx/499 诊断规则

新增 `scripts/doctor.sh`，默认检查近期 Nginx 日志并按以下类别输出有限摘要：

- 应用客户端错误：400-498，按状态、方法和归一化路径聚合。
- 客户端断开：499 单独统计，标明其不是应用响应。
- 服务端错误：5xx 单独聚合并使诊断失败。
- 已知测试探针：仅在请求特征可证明时标记，例如固定 `91001,91002,91003`；不能仅凭 User-Agent 排除。
- 高价值规则：新增路由 405、ZIP 格式 409、批量请求 422、刷新令牌 401、SSE 404、上传 499。

诊断输出包含时间窗口、计数、最近一次时间、端点、request ID 样本和建议动作，不输出 Authorization、Cookie、签名参数或完整超长查询串。无日志文件时给出“未检查”而不是“正常”。

## 统一验证入口

新增 `scripts/verify.sh`：

- `quick`：Shell 语法、脚本测试、API 文档一致性、聚焦后端与前端测试、前端类型/构建检查。
- `full`：在 quick 基础上执行完整后端测试、基础设施验证、Compose 配置及相关浏览器测试。
- `--allow-blocked`：只允许把明确依赖 sudo、Windows CAD worker 或未启动外部服务的检查标成 blocked；测试失败仍返回非零。

验证脚本保留每个门禁的独立退出状态和简短摘要，不通过管道掩盖真实失败。

## 文档

- 新增 `scripts/README.md`，说明启动、停止、状态、诊断、验证、数据库、Windows 转发、CAD worker 和存储维护的适用场景及退出码。
- 在 `docs/api.md` 的生成源中补充 ZIP 预检请求、响应、错误码和 TOCTOU 边界。
- 在 `docs/operations.md` 记录 405 代码漂移、409 ZIP 不完整和 499 客户端断开的排查流程。
- 保持 `make docs-generate` 与 `make docs-check` 通过。

## 测试与验收

### 后端

- 预检在源格式完整、结果格式部分缺失、两种格式完整、重复 ID、源文件缺失和无权限时返回正确结果。
- 预检和正式 ZIP 使用同一解析规则；正式 ZIP 仍拒绝不完整格式和存储缺失。
- 批量文件夹删除路由保持原子回滚、去重、活动 Job 取消和结果文件删除测试。

### 前端

- 弹窗默认选择源格式并自动预检。
- 不完整格式显示缺失数量且不能勾选或提交。
- 两种格式完整时均可下载。
- 预检失败与正式 409 后弹窗不关闭，用户输入不丢失。
- 单、多文件夹打包都传递正确源格式和文件 ID；单、多文件夹删除都只调用一次原子接口。

### scripts

- 测试代码时间晚于进程、前端源码晚于 dist、日志不存在、405/409/499 聚合和敏感查询脱敏。
- `bash -n scripts/*.sh`、聚焦 pytest、前端构建、完整文档检查均通过。
- 重启本地后端后，健康检查通过，批量删除路径不再返回 405；不得破坏当前用户数据。
