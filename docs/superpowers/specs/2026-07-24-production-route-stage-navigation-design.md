# PRODUCTION ROUTE 阶段导航与产物下载设计

## 目标

把生产批次详情页左侧 `PRODUCTION ROUTE` 从静态阶段列表改为可点击的阶段导航。点击任意阶段只切换右侧查看内容，不改变服务端认定的当前阶段，也不允许历史阶段或未来阶段越级执行。

每个已经产生正式产物的阶段都提供阶段级压缩包下载。其中“DXF 分类与分流”阶段必须能够下载分流后的 DXF 图纸、分类报告和分类清单组成的 ZIP。生产流程继续禁止单个生产文件下载。

“DXF 分类与分流”的逐文件结果默认收起，页面首先展示关键统计和下载动作，避免长清单淹没操作区。

第三步“图纸分类与拆板”本次继续保持占位，不接入拆板执行器。页面不得用定时器、分类进度或估算值伪造拆板进度。

## 已选方案

采用“查看阶段与执行阶段分离”的阶段工作台：

- 浏览器维护一个 `selectedStageCode`，只负责决定右侧展示哪个阶段。
- 服务端返回的 `current_stage` 是唯一执行依据。
- 阶段按钮全部可以点击；历史阶段显示只读结果，当前阶段显示服务端允许的操作，未来阶段显示只读合同和锁定原因。
- 查看非当前阶段时，页面明确提示“正在查看历史阶段”或“该阶段尚未解锁”，并提供“返回当前阶段”按钮。
- 工作流刷新或推进后，如果当前查看的是旧阶段，继续保留只读查看；如果所选阶段已不存在，则回到新的当前阶段。

未采用的方案：

- 把阶段按钮直接当作执行入口：容易把查看行为和状态变更混在一起，存在越级执行风险。
- 禁止点击未来阶段：安全但无法提前查看所需输入和正式产物合同，不利于生产准备。
- 为每类阶段单独建设下载接口：会重复文件权限、ZIP 构建、传输登记和审计逻辑。

## 页面结构

### 阶段导航

每个阶段使用真实的 `<button type="button">`，保留序号、阶段名称、执行状态和实现状态。样式同时区分：

- `is-current`：服务端当前阶段。
- `is-selected`：右侧正在查看的阶段。
- `is-complete`：已经成功或跳过的历史阶段。
- `is-failed`：失败阶段。
- `is-locked`：尚未推进到的未来阶段。

`aria-current="step"` 只标记服务端当前阶段；按钮通过可见文本和选中样式表达查看状态。键盘用户可以依次聚焦并打开各阶段。

### 阶段工作台

工作台标题、状态、阶段合同、错误、任务记录和产物均绑定所选阶段。阶段动作遵循以下矩阵：

| 所选阶段 | 查看 | 下载已有阶段 ZIP | 上传/执行/确认 |
| --- | --- | --- | --- |
| 已完成历史阶段 | 允许 | 有可用产物时允许 | 禁止 |
| 服务端当前阶段 | 允许 | 有可用产物时允许 | 仅按当前状态和能力开放 |
| 未解锁未来阶段 | 允许只读预览 | 无产物时不可用 | 禁止 |
| 当前失败阶段 | 允许 | 已有可用产物时允许 | 仅允许服务端声明的重试或确认 |

所有 mutation 在调用前再次核对 `selectedStage.stage_code === detail.current_stage`。执行和人工确认仍使用由服务端当前阶段解析出的阶段代码，不能使用任意点击值。

输入阶段在历史查看模式下只展示冻结摘要，不允许再次上传、删除、转换或冻结。Excel 第一阶段在非当前状态下隐藏运行按钮。分类分流阶段只有在它是当前阶段且状态允许时才能启动或重试。

## 阶段压缩包

新增阶段级下载端点：

`GET /api/v1/workflows/{workflow_id}/stages/{stage_code}/download-archive`

端点复用完整工作流压缩包已有的：

- 项目成员权限校验。
- Artifact 到 Files/Jobs Result 的文件解析。
- 文件读取权限校验。
- 注册文件 ZIP 构建。
- outbound 传输登记、审计日志和流式清理。

端点只收集指定 `stage_run_id` 下已登记且可用的 artifact。ZIP 内目录固定为：

`workflow-{workflow_id}/{sequence}_{stage_code}/{artifact_type}/{original_name}`

同名文件继续使用现有文件 ID 去重规则。下载文件名为：

`workflow-{workflow_id}-{sequence}_{stage_code}.zip`

错误合同：

- 阶段不存在：`WORKFLOW_STAGE_UNKNOWN`，HTTP 404。
- 阶段没有 artifact：`WORKFLOW_STAGE_ARCHIVE_EMPTY`，HTTP 409。
- 已登记 artifact 对应文件缺失或已删除：`WORKFLOW_ARCHIVE_ARTIFACT_MISSING`，HTTP 409。
- 非项目成员：沿用现有项目权限拒绝。

前端只在所选阶段存在 artifact 时启用“下载本阶段结果压缩包”。“DXF 分类与分流”的按钮文案为“下载分流结果压缩包”，其他阶段使用通用文案。完整生产压缩包按钮继续保留在全局产物区。

## 分流结果简化

分类完成后默认展示：

- 输入、已分类、待确认、无法读取四个计数。
- BH、BOX、BT 等类型分组计数。
- 分类器版本和输入清单摘要。
- “下载分流结果压缩包”主按钮。

逐文件结果放入默认关闭的折叠区，标题为“查看文件明细（N）”。展开后：

- 每页显示 10 条。
- 只展示文件名、分类/类型、目标目录和异常提示。
- 不再展示源文件 ID、输出文件 ID 等内部标识。
- 文件名和目标目录允许自动换行。
- 不提供单文件下载按钮。

这套简化同时适用于未来“图纸分类与拆板”产生真实结果后的明细展示；当前占位阶段只展示合同和未实现状态，不伪造文件列表或下载按钮。

## 图纸分类与拆板占位合同

第三步的占位面板明确展示“拆板执行能力尚未接入”，并列出未来正式实现时必须由服务端提供的项目级指标：

- 总进度：`completed_count / total_count` 和对应百分比。
- 实时速度：使用最近一段已完成图纸的服务端完成时间计算，单位为“张/分钟”。
- 预计剩余时间：只有已产生有效速度且仍有未完成图纸时显示。
- 结果统计：自动完成、待人工处理、失败数量。

本次所有指标显示为“未接入”，不显示 `0 张/分钟`，避免把未执行误解为执行速度为零。该阶段没有开始、重试、确认或下载按钮；它的 `implementation_status` 继续是 `placeholder`，工作流不能通过点击阶段按钮越级进入或完成它。

分类分流阶段的进度仍只代表分类分流任务，不复用或冒充拆板项目总进度。将来接入拆板执行器时，进度必须以整张 DXF 事务完成为计数边界，并由服务端持久化；浏览器只轮询读取权威数据。

## 数据流与状态正确性

阶段选择是纯前端查看状态，不写入 URL 之外的服务端状态，也不触发 start、execute、complete、cancel、upload、freeze 或 download。

下载只读取已经登记的 artifact，不改变工作流阶段。ZIP 构建失败时不推进流程；传输失败通过现有 outbound transfer settlement 记录。完整工作流下载与阶段下载都不允许绕过生产文件的压缩包边界。

阶段推进后刷新 workflow detail 和相关阶段查询。当前阶段动作成功后自动选中新当前阶段，避免操作员停留在已完成阶段却误以为仍可继续操作。用户主动点击历史阶段后，普通后台轮询不抢回选择。

## 测试与验收

后端自动化测试覆盖：

- 阶段 ZIP 只包含该阶段 artifact，不包含其他阶段文件。
- 分流阶段 ZIP 包含 `classified_dxf`、`classification_report` 和 `classification_manifest`。
- 空阶段、未知阶段、缺失文件和越权请求返回稳定错误。
- OpenAPI 暴露阶段 ZIP GET，且生产单文件下载限制保持不变。
- 阶段下载完成后存在 outbound transfer 和审计记录。

前端浏览器测试覆盖：

- 点击历史阶段后右侧标题切换，但执行请求仍不能发生。
- 点击未来阶段只显示锁定提示、合同和不可用下载状态。
- 第三步占位面板显示项目总进度、实时速度和预计剩余时间的未接入合同，不显示伪造数值或动作按钮。
- 返回当前阶段后恢复真实操作按钮。
- 分类完成后默认看不到长表，展开后每页最多 10 条且不显示文件 ID。
- 点击“下载分流结果压缩包”只发起阶段 ZIP GET。
- 工作流推进后自动选中新当前阶段；轮询刷新不会打断用户主动查看历史阶段。

最终验收还要实际生成一个包含多个分流 DXF、报告和清单的 ZIP，检查压缩包成员路径、数量、扩展名与内容头；并在真实浏览器中完成阶段切换、折叠明细和下载。
