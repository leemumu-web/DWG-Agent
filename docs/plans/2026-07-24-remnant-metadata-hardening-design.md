# 余料附加信息与导出安全加固设计

## 背景

余料导入确认已支持项目编号二、库存位置、备注一和备注二，并允许这些字段为空。现有批量界面会同时提交项目编号二和库存位置，导致工人只修改其中一项时可能清空另一项；后端也没有统一区分“未提交字段”和“明确清空字段”。同时，Excel 导出会直接写入工人可编辑文本，存在被 Excel 解释为公式的风险。

## 目标

- 未选择更新的字段保持原值。
- 明确选择更新且输入为空时清空字段。
- 没有选择任何批量字段时拒绝请求，并返回中文错误。
- 单行导入项编辑对省略、`null` 和空字符串采用一致语义。
- Excel 中所有外部文本均按普通文本导出，不执行公式。
- 不改变正式余料表结构、现有路由路径、删除后重导和审计留存语义。

## 接口语义

批量附加信息接口继续使用：

`POST /api/v1/remnant-import-batches/{batch_id}/bulk-optional-metadata`

请求中字段是否出现即为更新掩码：

- 字段未出现：保持原值。
- 字段出现且为非空文本：规范化后写入。
- 字段出现且为 `null`、空字符串或仅空白：清空为 `NULL`。
- 四个附加字段均未出现：返回 `422 REMNANT_OPTIONAL_METADATA_REQUIRED`，中文信息为“请至少选择一项需要批量更新的附加信息。”

单行导入项编辑采用同一规则。必填字段原有语义不变。

## 网页交互

批量附加信息弹窗为项目编号二和库存位置分别提供“更新此字段”开关：

- 默认均未选择，确认按钮不可提交。
- 选择后显示对应输入框。
- 输入为空时显示“将清空所选图纸的该字段”的提示。
- 请求体只包含已选择字段。
- 成功消息按实际更新字段显示。

备注一和备注二继续通过单行编辑维护，本次不扩大批量界面范围。

## Excel 安全

导出层对所有字符串值执行统一安全转换。若去除前导空白后的首字符为 `=`、`+`、`-` 或 `@`，在原字符串前增加单引号，使 Excel 将其作为文本。数字和日期保持原有类型与格式。

## 测试与验收

- 后端单元测试覆盖省略字段、显式清空和无字段拒绝。
- API 测试覆盖中文错误与审计内容。
- 导出测试覆盖四类公式前缀及普通文本不变。
- Playwright 覆盖只更新一个字段、明确清空和未选择字段不可提交。
- 运行 Ruff、余料后端测试、解析 Stage、前端生产构建和余料 Playwright。
